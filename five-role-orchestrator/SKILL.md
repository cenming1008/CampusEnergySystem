# Skill 名称

`five-role-orchestrator`

兼容口径：

- 当前正式入口为 `five-role-orchestrator`。
- 旧称 `five-thread-orchestrator` 仅作为历史别名理解，不再作为推荐命名。
- 本 skill 的正式协作语义按“五角色协作法”理解。

## 作用

- 作为“五角色协作体系”的总控调度入口使用。
- 先读取主区文档和当前执行依据，再判断当前任务所处主题与阶段。
- 根据已有规则选择最合适的角色路径，而不是直接进入实现。
- 生成下一棒角色可直接接手的 prompt 骨架，并明确允许范围、非目标、风险、验证要求与回写要求。
- 给下一棒附带最小执行协议，使其知道“能做什么、不能做什么、做到什么算完成、失败后退回哪里”。
- 在需要决策但证据不足时，保留人类拍板点，不替代人类做高风险范围判断。

## 适用场景

- 新任务进入后，需要先判断它是否属于当前主主题。
- 当前任务还不能直接交给前端或后端，需要先做角色分流。
- 需要在预判、规则、前端、后端、验收之间选择一条最短可闭环路径。
- 需要输出下一棒角色可直接使用的接力 prompt。
- 需要保留“是否继续当前主题 / 是否新开主题 / 是否进入收口判断”等拍板点。

## 输入

- 当前任务描述
- 当前主区上下文
- `AGENTS.md`
- `docs/plans/current-status.md`
- `docs/plans/handoff.md`
- 当前主题对应 `PLAN-*.md`（如存在）
- `docs/guides/product-positioning.md`
- `docs/guides/five-thread-vibe-coding-framework.md`

## 输出

- 当前主题判断
- 当前任务路径判断
- 建议下一棒角色
- 当前允许范围
- 当前非目标
- 当前风险
- 下一棒角色执行协议
- 下一棒 prompt 骨架
- 必要的人类拍板点

## 不负责什么

- 不直接承担前端、后端或其他实现角色的大规模代码改动。
- 不替代预判、规则、前端、后端、验收各角色的专用模板本体。
- 不把当前仓库全部协作规则一次性重写进一个文件。
- 不在证据不足时擅自新开主题、扩张范围或批准 breaking change。
- 不把“总控调度”误做成“实现角色”或“全仓清理角色”。
- 不把 harness 协议层写成覆盖全部场景的重型流程手册。

## 必读入口

使用本 skill 时，先按以下顺序建立上下文：

1. `AGENTS.md`
2. `docs/plans/current-status.md`
3. `docs/plans/handoff.md`
4. 当前主题对应 `PLAN-*.md`（如存在）
5. `docs/guides/product-positioning.md`
6. `docs/guides/five-thread-vibe-coding-framework.md`

若任务已经明确落入具体实现，再由下一棒角色继续补读对应 guide；总控层本身不展开实现细节。

## 当前角色体系

当前 skill 默认服务于以下五角色协作体系：

- 预判：负责分析、归因、拆路径和最小修复路径判断。
- 规则：负责主题、术语、边界和文档口径收敛。
- 前端：负责页面、组件、状态、路由与前端交互实现。
- 后端：负责接口、schema、service、权限和返回结构实现。
- 验收：负责阶段核对、是否继续推进、是否进入收口判断。

总控调度器本身不替代这五个角色，而是做三件事：

- 判断当前任务应该进入哪条路径。
- 说明为什么走这条路径。
- 给下一棒角色生成可直接接力的 prompt 骨架。

当前版本在这三件事之外，再补一层最小 harness 约束：

- 为下一棒补齐权限边界。
- 为下一棒补齐验证协议。
- 为下一棒补齐回写协议。
- 为下一棒补齐停机与升级规则。

## 目录说明

- `prompts/orchestrator.md`
  用于总控角色本身的 prompt 骨架，负责主区读取、主题判断、路径选择、拍板点保留与接棒输出。

- `prompts/prejudge.md`
  用于预判角色的骨架提示，只承载预判角色的职责、边界、输出格式与待补项。

- `prompts/rules.md`
  用于规则角色的骨架提示，只承载规则角色的职责、边界、输出格式与待补项。

- `prompts/frontend.md`
  用于前端角色的骨架提示，只承载前端角色的职责、边界、输出格式与待补项。

- `prompts/backend.md`
  用于后端角色的骨架提示，只承载后端角色的职责、边界、输出格式与待补项。

- `prompts/acceptance.md`
  用于验收角色的骨架提示，只承载验收角色的职责、边界、输出格式与待补项。

- `templates/next-role-prompt-template.md`
  用于生成“下一棒 prompt”的通用模板，重点描述当前主题、路径判断、允许范围、非目标、风险、验证协议、回写协议、停机/升级规则和接力 prompt。

- `templates/role-execution-contract-template.md`
  用于生成“下一棒角色执行协议”的通用模板，重点描述权限边界、验证协议、回写协议、停机规则、升级规则与完成定义。

- `templates/topic-routing-template.md`
  用于生成“当前任务应走哪条角色路径”的判断模板，适合在总控层快速输出分流结论。

- `templates/closure-decision-template.md`
  用于生成“是否阶段完成、是否继续保留主题、是否进入 archive 判断”的收口模板。

- `examples/`
  用于存放极简示例骨架，帮助后续补齐“新主题进入”“继续当前主题”“收口判断”等典型场景。

## 推荐工作流

推荐按以下顺序使用本 skill：

1. 读取主区文档，先建立当前主题上下文。
2. 判断当前任务是否属于当前主主题。
3. 判断当前任务更适合进入预判、规则、前端、后端还是验收。
4. 如需继续推进，输出一条最短可闭环路径，而不是同时拉起所有角色。
5. 生成下一棒角色可直接使用的 prompt 骨架。
6. 为下一棒附带最小执行协议：权限边界、验证协议、回写协议、停机/升级规则。
7. 标出当前允许范围、当前非目标、当前风险和必要的人类拍板点。

这个工作流的重点不是“替下一棒做决定”，而是“让下一棒在边界清晰的前提下开工”。

## 最小闭环定义

在本 skill 中，“最小闭环”指的是总控层至少完成以下结果：

- 已读取主区核心入口。
- 已给出当前主题判断。
- 已给出一条建议角色路径。
- 已明确下一棒角色是谁。
- 已给出下一棒角色执行协议。
- 已生成下一棒 prompt 骨架。
- 已说明当前允许范围、非目标、风险、验证要求与回写要求。
- 如存在未定事项，已明确保留人类拍板点。

若以上内容尚未具备，就不应视为总控调度完成。

## 当前实现策略

当前版本采用“轻量 harness 入口”策略，仍保持克制：

- 优先提供结构，不一次性写满全部规则细则。
- 优先固化总控层职责，不把各角色模板正文塞进 `SKILL.md`。
- 优先保留占位与 TODO，方便后续逐步补充。
- 优先复用仓库里已经存在的主区文档、PLAN 与 guide，不擅自引入新的治理机制。
- 优先在 `templates/` 中补协议层，不把 `SKILL.md` 膨胀成操作手册。

换句话说，本 skill 当前是“轻量 harness 入口”，而不是“完整的五角色执行大全”。
