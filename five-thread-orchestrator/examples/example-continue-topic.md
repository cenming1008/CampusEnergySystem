# 场景

这是一个“继续当前主题”的示例。

目标是演示：当前已经有主主题、主区文档和正式 PLAN 时，总控线程如何判断当前任务仍不仍属于该主题，以及下一棒应该交给谁。

## 背景

当前主主题已经切换到“命名迁移分层治理”。

规范线程已经锁定正式产品口径，前端 / 文档线程也完成了一轮主入口命名修正。用户此时继续追问：“那下一棒该给谁？要不要继续处理脚本和后端里的低风险说明文案？”

这个阶段已经不是“要不要新开主题”，而是“当前主题继续推进时，应该交给哪个线程”。

## 用户输入

用户说：

“当前主入口文案已经改完了，README 和新手入口都切到园区 EMS 口径了。现在要继续推进的话，下一棒应该交给谁？”

## 总控线程判断结果

- 当前主主题：命名迁移分层治理
- 当前任务是否仍属于当前主主题：属于
- 当前线程路径走到哪一步：已完成 `探索 -> 规范 -> 前端`，准备决定是否进入低风险补充轮或直接验收
- 下一棒建议交给谁：优先交给验收；若用户明确要求继续低风险说明文案收敛，则交给后端 / 脚本线程
- 是否需要用户拍板：需要
  - 是否只停在“主入口命名修正”阶段
  - 是否再开一轮低风险文案收敛

## 下一棒线程

- 下一线程：验收
- 为什么：
  - 主入口目标已经完成，下一步最重要的是先判断是否达到阶段完成
  - 在未确认还要不要继续时，不应默认直接打回实现线程
- 本轮不该交给谁：
  - 不应直接交前端，因为主入口前端任务已经完成
  - 不应直接交规范，除非边界再次发生变化

## 示例 prompt 输出摘要

下一棒 prompt 摘要可写成：

- 对照当前 PLAN、`current-status.md`、`handoff.md`
- 核对主入口命名是否已统一到园区 EMS 口径
- 判断当前是否达到阶段完成
- 判断是否还需要继续保留当前主主题
- 若准备继续推进，明确下一轮只允许处理哪些低风险文案

## 说明

这个示例主要说明：当主题已经在推进中时，总控线程的重点是判断“当前走到哪一步、下一棒交给谁”，而不是重新做一轮主题立项。
