# 统一设备管理系统使用指南

> **版本**: v2.2.0  
> **更新日期**: 2026-01-24  
> **状态**: ✅ 已完成重构

---

## 🎯 概述

全新的统一设备管理系统将所有设备类型整合到一起，提供：

- ✅ **智能设备创建** - 根据设备类型自动配置
- ✅ **统一数据接口** - 一个接口处理所有能源数据
- ✅ **自动分类归档** - 自动识别能源类型和设备类别
- ✅ **配置化扩展** - 添加新设备类型只需配置
- ✅ **碳排放追踪** - 自动计算所有能源的碳排放

## 📋 支持的设备类型

系统内置 11 种设备类型，覆盖 6 种能源：

### ⚡ 电力系统 (5种)

| 设备类型 | 标识 | 单位 | 说明 |
|---------|------|------|------|
| 用电设备 | `load` | kW | 各类用电负荷 |
| 光伏发电 | `solar` | kW | 太阳能发电系统 |
| 风力发电 | `wind` | kW | 风力发电系统 |
| 储能设备 | `storage` | kWh | 电池储能系统 |
| 充电桩 | `charger` | kW | 电动车充电设备 |

### 💧 水系统 (1种)

| 设备类型 | 标识 | 单位 | 说明 |
|---------|------|------|------|
| 水表 | `water_meter` | m³/h | 水流量计量 |

### 🔥 燃气系统 (1种)

| 设备类型 | 标识 | 单位 | 说明 |
|---------|------|------|------|
| 燃气表 | `gas_meter` | m³/h | 天然气计量 |

### 🌡️ 热力系统 (2种)

| 设备类型 | 标识 | 单位 | 说明 |
|---------|------|------|------|
| 热量表 | `heat_meter` | GJ/h | 热力计量 |
| 蒸汽表 | `steam_meter` | t/h | 蒸汽计量 |

### ❄️ 制冷系统 (1种)

| 设备类型 | 标识 | 单位 | 说明 |
|---------|------|------|------|
| 冷量表 | `cooling_meter` | kW | 冷量计量 |

      "unit": "m³/h",
      "default_capacity": 50.0,

      "optional_fields": ["pressure", "temperature", "quality_index"],
      "icon": "💧",

### 2. 智能创建设备

使用新的智能创建接口，系统会自动配置所有字段：

```bash
POST /devices/
Content-Type: application/json

{
  "name": "1号水表",
  "sn": "WATER001",
  "device_type": "water_meter",
  "location": "A栋1层"
}
```

**系统自动设置**:
- ✅ `energy_type`: "water"
- ✅ `device_category`: "water_meter"
- ✅ `unit`: "m³/h"
- ✅ `rated_capacity`: 50.0 (默认值)

**响应示例**:

```json
{
  "id": 1,
  "name": "1号水表",
  "sn": "WATER001",
  "device_type": "water_meter",
  "device_category": "water_meter",
  "energy_type": "water",
  "unit": "m³/h",
  "rated_capacity": 50.0,
  "location": "A栋1层",
  "is_active": true
}
```

### 3. 统一数据上报

所有设备使用同一个接口上报数据：

```bash

Content-Type: application/json
```

  "pressure": 0.3,

## 🔧 添加新设备类型

### 步骤 1: 编辑设备注册表

打开 `app/core/device_registry.py`，添加新设备类型：

```python
# 示例：添加压缩空气表
self.register(DeviceTypeConfig(
    device_type="air_meter",
    category=DeviceCategory.LOAD,  # 或创建新类别
    energy_type=EnergyType.ELECTRICITY,  # 或创建新能源类型
    name_zh="压缩空气表",
    name_en="Compressed Air Meter",
    unit="m³/h",
    default_capacity=100.0,
    required_fields=["consumption", "flow_rate"],
    optional_fields=["pressure", "temperature"],
    icon="💨",
    color="#00BCD4"
))
```

### 步骤 2: 重启服务

```bash
docker restart campus_backend
# 或
python run.py
```

### 步骤 3: 使用新设备类型

```bash
POST /devices/
{
  "name": "1号空气表",
  "sn": "AIR001",
  "device_type": "air_meter"
}
```

完成！无需修改其他代码。

## 🎓 最佳实践

### 1. 设备命名规范

- ✅ 好: "1号水表"、"A栋光伏"、"主配电柜"
- ❌ 差: "设备1"、"test"、"aaa"

### 2. 序列号管理

- 建议格式: `{类型前缀}{编号}`
- 示例: `WATER001`, `SOLAR-A01`, `GAS_ROOM1_001`

### 3. 位置信息

- 建议包含: 建筑物 + 楼层 + 房间
- 示例: "A栋3层配电室"、"B栋屋顶"

### 4. 数据上报频率

| 设备类型 | 推荐频率 |
|---------|---------|
| 电力设备 | 1-5分钟 |
| 水表 | 5-15分钟 |
| 燃气表 | 5-15分钟 |
| 热量表 | 10-30分钟 |

### 5. 数据验证

上报数据前进行基本验证：

```python
def validate_data(device_type, data):
    # 检查必需字段
    if "consumption" not in data:
        raise ValueError("缺少 consumption 字段")
    
    # 检查数值范围
    if data["consumption"] < 0:
        raise ValueError("consumption 不能为负数")
    
    # 电力设备特殊检查
    if device_type in ["load", "solar"]:
        if "voltage" in data and not (180 <= data["voltage"] <= 260):
            logger.warning(f"电压异常: {data['voltage']}V")
```

## 🐛 故障排查

### 问题 1: 创建设备失败 "不支持的设备类型"

**原因**: 提供的 `device_type` 不在注册表中

**解决**:
```bash
# 查看支持的设备类型
GET /devices/types

# 使用正确的 device_type
```

### 问题 2: 数据上报失败 "缺少必需字段"

**原因**: 未提供设备类型要求的必需字段

**解决**:
```bash
# 查看设备类型要求
GET /devices/types/{device_type}

# 确保提供所有 required_fields
```

### 问题 3: 序列号重复

**原因**: 系统中已存在相同的序列号

**解决**:
- 检查是否设备已存在
- 使用唯一的序列号

## 📊 架构对比

### 旧架构（v2.1.0 之前）

```
设备创建: POST /devices/ (手动填写所有字段)
电力数据: POST /telemetry/upload
多能源数据: POST /energy/data
查询: 分散在多个端点
```

```

统计: GET /devices/{id}/statistics
```

**优势**:
- ✅ API 更简洁统一
- ✅ 自动配置，减少错误
- ✅ 易于扩展
- ✅ 更好的类型安全

## 💡 常见问题

### Q: 旧的 API 端点还能用吗？

A: 可以。为了向后兼容，旧端点保留：
- `POST /devices/legacy` - 传统设备创建
- `POST /telemetry/upload` - 电力数据上报
- `POST /energy/data` - 多能源数据上报

但建议迁移到新的统一接口。

### Q: 如何知道某个设备支持哪些字段？

A: 使用 `GET /devices/types/{device_type}` 查看 `required_fields` 和 `optional_fields`。

### Q: 可以自定义碳排放因子吗？

A: 可以。编辑 `app/services/energy_service.py` 中的 `CARBON_FACTORS` 字典。

### Q: 如何添加新的能源类型？

A: 
1. 在 `app/models/tables.py` 的 `EnergyType` 枚举中添加
2. 在 `device_registry.py` 中注册使用该能源类型的设备
3. 在 `EnergyService.CARBON_FACTORS` 中添加碳排放因子
