# 串口通信入门

> 帮助理解「串口是什么、怎么传数据、常用参数和在本项目里怎么用」。

---

## 一、串口是什么？

**串口（Serial Port）** 是一种**按位依次传输**数据的通信方式：数据被拆成很多个「位」（0 或 1），在**一根（或一对）数据线**上**一个接一个**地传过去。

- **串行**：一个接一个传，像排队过门。
- 和它相对的是**并行**：多根线同时传多个位（例如 8 根线一次传 1 字节），速度可以更快，但线多、距离一长就易受干扰，所以工业、嵌入式里远距离常用**串行**。

串口在工业、物联网里非常常见：电表、传感器、PLC、单片机、模块（如 4G、LoRa）很多都留一个串口，用统一的标准（波特率、数据位等）就能和电脑或网关通信。

---

## 二、谁和谁在通信？

典型关系是**两台设备**（例如「电脑 ↔ 电表」或「网关 ↔ 传感器」）：

- **A 的发送（TX）** 接 **B 的接收（RX）**
- **B 的发送（TX）** 接 **A 的接收（RX）**
- **地线（GND）** 共地

所以至少需要 **3 根线**：TX、RX、GND。数据是「你发我收、我发你收」的两条单向通道。

```
  [ 电脑/网关 ]                    [ 电表/设备 ]
       TX  ──────────────────────→  RX
       RX  ←──────────────────────  TX
      GND  ─────────────────────── GND
```

---

## 三、物理层：电平标准（为什么有 RS-232、RS-485、TTL）

「位」在线上用**电压**表示：高电平表示 1，低电平表示 0。不同标准规定的电压不一样，不能混用。

| 类型 | 电平大致范围 | 常见用途 |
|------|--------------|----------|
| **TTL** | 0V = 0，3.3V 或 5V = 1 | 单片机、树莓派、USB 转 TTL 模块、很多模块的「串口」引脚 |
| **RS-232** | 负电压表示 1，正电压表示 0（±12V 等） | 老式电脑 COM 口、部分工业设备 |
| **RS-485** | 两根线 A/B 的**差分电压**表示 0 和 1 | 工业现场、多设备总线、抗干扰、可长距离 |

要点：

- 你电脑没有「真正的」串口时，常用 **USB 转 TTL** 或 **USB 转 RS-232/RS-485** 的转接器，驱动会虚拟出一个「串口设备」（如 `/dev/cu.usbserial-xxx`、`COM3`）。
- 和设备对接前，要确认设备是 **TTL 电平** 还是 **RS-232/RS-485**，再选对应的转接器和接线方式。

## 四、通信参数（两边必须一致）

串口传的是一串 0/1，要正确还原成「字节」和「一帧一帧的数据」，收发双方必须约定好下面几项。

### 4.1 波特率（Baud Rate）

- **含义**：每秒传多少**个位**（bit）。
- **常见值**：9600、19200、38400、115200 等。
- **要求**：电脑/网关和设备**必须设成同一个**，否则收到的全是乱码。

例如 9600 波特率：每秒 9600 位，传 1 个字节（8 位）大约要 1/1200 秒。

### 4.2 数据位（Data Bits）

- **含义**：每个「字」用几个位表示，一般选 **8**（即 1 字节）。
- 常见：7 或 8。8 最常用。

### 4.3 停止位（Stop Bits）

- **含义**：每个字后面跟几个「停止位」，表示这个字发完了。
- 常见：**1 位**。少数设备用 2 位。

### 4.4 校验位（Parity）

- **含义**：用 1 个位做简单校验，帮助发现传输错误。
- **无校验（None）**：不加校验位，最常用。
- **奇校验（Odd）**：让「数据位 + 校验位」里 1 的个数为奇数。
- **偶校验（Even）**：让 1 的个数为偶数。

**常见组合**：**8N1** = 8 数据位、无校验、1 停止位。设备手册里常写「9600, 8, N, 1」或「9600 8N1」。

## 五、一帧数据长什么样？（脑子里有个图）

可以这样想：

1. **空闲**：线处于某一固定电平（例如高）。
2. **起始位**：拉低 1 位时间，表示「下面开始一个字的传输」。
3. **数据位**：从低到高依次发 8 位（或 7 位），表示一个字节。
4. **校验位**（若有）：1 位。
5. **停止位**：1 位（或 2 位），拉高，表示这个字结束。

所以「一帧」= 起始位 + 数据位 + 校验位 + 停止位。例如 8N1 时，一帧 = 1 + 8 + 0 + 1 = 10 位。  
设备按固定间隔、一帧一帧地发，接收方用**相同的波特率、数据位、停止位、校验**去采样，就能还原出一个个字节。

## 六、从字节到「协议」

串口只负责**传字节流**，不规定这些字节代表什么。  
所以：

- 有的设备是「**文本协议**」：每行一串字符，例如 `"VOLTAGE=220.5\r\n"`，你用 `readline()` 按行读，再解析。
- 有的是「**二进制协议**」：例如 Modbus RTU，一帧里包含：从站地址、功能码、寄存器地址、数据、CRC。你要按协议文档**按字节解析**，而不是当文本。

也就是说：**串口 = 底层传输；上面还有一层「协议」**（文本或 Modbus 等），协议规定了「哪几个字节是什么含义」。

## 七、在本项目里怎么用串口

### 7.1 依赖与端口路径

- 安装：`pip install pyserial`
- 端口路径示例：
  - **Mac**：`/dev/cu.usbserial-xxxx` 或 `/dev/tty.usbserial-xxxx`（插上 USB 转串口后可用 `ls /dev/cu.*` 查看）
  - **Linux**：`/dev/ttyUSB0`、`/dev/ttyS0` 等
  - **Windows**：`COM3`、`COM4` 等（设备管理器里看）

### 7.2 测试脚本：只验证「能否打开、能否收到数据」

项目里提供了 `scripts/python/test_serial_port.py`，**不连 MQTT**，只做两件事：

1. 用你指定的**端口**和**波特率**打开串口；
2. 读若干**行**（或原始字节），在终端打印出来。

用法示例：

```bash
# Mac：先查端口
ls /dev/cu.*

# 读 5 行（默认），波特率 9600
python scripts/python/test_serial_port.py --port /dev/cu.usbserial-xxx --baud 9600 --lines 5
```

若设备发的是**文本**（每行以 `\r`/`\n` 结尾），你会看到可读的一行行内容；若是**二进制**，脚本会尝试用 UTF-8 解码，失败则打印十六进制。  
能稳定看到有数据，就说明：**端口、波特率、接线**没问题，下一步是根据设备协议解析这些字节，再在 `device_gateway.py` 里组 JSON 发 MQTT。

### 7.3 常用代码模式（pyserial）

```python
import serial

# 打开（端口、波特率、超时；数据位/停止位/校验一般用默认 8N1）
ser = serial.Serial("/dev/ttyUSB0", 9600, timeout=1)

# 按行读（适合文本协议，设备每行一条数据）
line = ser.readline()   # 返回 bytes，可能带 \r\n
text = line.decode("utf-8", errors="replace").strip()

# 按字节数读（适合二进制协议，如 Modbus RTU）
n = ser.read(10)   # 读 10 个字节

# 写（若需要向设备发指令）
ser.write(b"GET\r\n")

ser.close()
```

## 八、串口和 Modbus 的关系

- **Modbus** 是一种**应用层协议**：规定「从站地址、功能码、寄存器地址、数据、CRC」等。
- **Modbus RTU**：把这套协议放在**串口**上传输（一帧一帧的字节，带 CRC）。
- **Modbus TCP**：把同一套协议放在 **TCP 网络**上传输（你项目里的 `test_modbus_tcp.py` 就是这种）。

所以：**串口是「路」，Modbus 是「路上跑的格式」**。先理解串口「怎么传字节」，再学 Modbus「这些字节按什么规则排列」，会更容易。

## 九、学习顺序小结

1. **概念**：串口 = 串行、按位传；需要 TX/RX/GND；电平有 TTL/RS-232/RS-485。
2. **参数**：波特率、8N1 等，两边一致才能正确收数据。
3. **数据**：串口传的是字节流；上面还有「协议」（文本或 Modbus 等）需要按文档解析。
4. **动手**：用 `test_serial_port.py` 确认能收到数据，再用 `device_gateway.py` 里串口相关逻辑做解析和 MQTT 上报。

遇到具体设备时，重点看其**说明书**里的：串口参数（波特率、数据位、停止位、校验）、是文本协议还是二进制（若为 Modbus RTU，再查寄存器表），然后对照项目里的脚本和文档逐步调试即可。
