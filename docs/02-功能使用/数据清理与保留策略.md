# 数据清理与保留策略

> 统一说明手动清理、自动清理、页面影响范围和建议保留策略，替代旧的分散说明文档。

---

## 适用场景

本说明适用于以下场景：

- 需要从前端页面执行历史数据清理
- 需要通过 SQL 精确删除某类能源或某个设备的数据
- 需要理解自动清理策略和数据保留边界
- 需要评估清理操作对页面、报表和预测的影响

---

## 数据来源与影响范围

多能源管理页面的统计和趋势数据主要来自 `energydata` 表，常见读取入口为：

- `GET /energy/statistics`
- 相关设备与能源统计接口

清理 `energydata` 后，通常会影响：

- 多能源管理页面
- 驾驶舱中的能源统计
- 报表导出中的历史数据
- 趋势分析与部分预测训练数据

通常不会直接影响：

- 设备信息
- 用户信息
- 已独立存储的报警记录

---

## 推荐清理方式

### 1. 页面清理

推荐优先使用系统内的数据清理入口，例如：

`系统设置 -> 数据管理 -> 数据清理`

适合场景：

- 运维人员进行日常清理
- 按时间范围删除旧数据
- 需要保留统一确认和操作流程

### 2. SQL 精确清理

适合场景：

- 只删除某个设备的数据
- 只删除某个能源类型的数据
- 需要精确限定时间窗口

示例：

```sql
DELETE FROM energydata
WHERE timestamp >= NOW() - INTERVAL '7 days';
```

```sql
DELETE FROM energydata
WHERE device_id = 1
  AND timestamp >= NOW() - INTERVAL '7 days';
```

```sql
DELETE FROM energydata
WHERE energy_type = 'electricity'
  AND timestamp >= NOW() - INTERVAL '7 days';
```

### 3. 自动清理

自动清理适合长期保留策略，例如：

- 定期清理超过某个阈值的历史数据
- 保留聚合数据，减少明细膨胀
- 统一由定时任务执行

自动清理应优先满足：

- 规则清晰
- 有留存周期说明
- 有验证手段
- 不影响当前仍需查询的数据窗口

---

## 操作前检查

执行清理前建议至少确认：

1. 当前要删除的是测试数据还是生产数据
2. 是否已经完成数据库备份
3. 当前页面展示时间范围是否正落在待删除区间
4. 是否会影响报表、预测训练或验收留痕

---

## 清理后的验证

清理完成后建议验证：

1. 页面数据是否按预期归零或减少
2. 图表是否正确显示为空态
3. 报表接口是否仍能正常响应
4. 其他未清理数据是否未被误删

---
