# 设备接入调试指南

> 如何保证设备能向程序发送 JSON、以及如何调试串口 / Modbus / HTTP 等多种设备接口。

---

## 一、整体思路：分两层调试

```
[ 真实设备 ]  →  [ 采集/网关程序 ]  →  MQTT (JSON)  →  [ 后端 ]
    ① 先确保这一层能发出 JSON、后端能收到
    ② 再逐类调试设备接口（串口、Modbus、HTTP）
```

- **第一步**：先不接真实设备，用脚本或命令行往 MQTT 发 JSON，确认后端能收到并创建设备、入库、推前端。
- **第二步**：再按接口类型（串口、Modbus、HTTP）单独调试「设备 → 采集程序」，最后让采集程序按同一 JSON 格式发 MQTT。

---

## 二、调试「MQTT → 后端」：保证程序能收到 JSON

### 2.1 用项目自带脚本发一条测试 JSON（推荐）

确保后端和 MQTT 已启动后，在项目根目录执行：

```bash
# 安装依赖（若未装）
pip install paho-mqtt

# 发送一条，会触发即插即用（自动创建设备 TEST_DEVICE_001）
python scripts/python/mqtt_send_test.py

# 指定设备编码、名称、类型
python scripts/python/mqtt_send_test.py --code METER002 --name "2号电表" --type load

# 连续发 10 条（模拟周期上报）
python scripts/python/mqtt_send_test.py --code METER001 --loop 10
```

**如何验证**：

- 后端日志里应有类似：`MQTT 自动创建设备` 或 `设备数据上报成功`。
- 前端「设备台账」或「多能源管理」里出现对应设备及数据。

### 2.2 用 mosquitto_pub 命令行发 JSON

MQTT 容器/本机若装了 `mosquitto_pub`，可直接发一条 JSON：

```bash
# Docker 里
docker exec -it mine_mqtt mosquitto_pub -h localhost -t 'mine/telemetry' -m '{"device_code":"CLI_TEST_001","voltage":220,"current":5,"power":1.1,"energy":100}'

# 本机（Broker 在 localhost:1883）
mosquitto_pub -h localhost -p 1883 -t 'mine/telemetry' -m '{"device_code":"CLI_TEST_001","voltage":220,"current":5,"power":1.1,"energy":100}'
```

同样看后端日志和前端是否出现该设备与数据。

### 2.3 订阅 MQTT 看是否有消息（排查“没收到”）

```bash
# 订阅后端用的主题，看是否有发布
mosquitto_sub -h localhost -p 1883 -t 'mine/telemetry' -v
# 或 Docker
docker exec -it mine_mqtt mosquitto_sub -h localhost -t 'mine/telemetry' -v
```

另一终端用 `mqtt_send_test.py` 或 `mosquitto_pub` 发送，这里应能看到相同主题和 payload。若这里都收不到，说明问题在发布端或 Broker，不在后端。

---

## 三、第二步实操：按接口类型一步步做

第一步已确认「MQTT → 后端」正常后，按你手头的设备接口选一种做第二步。

**通用准备**（任选一种接口前都建议做）：

```bash
source venv/bin/activate
pip install paho-mqtt pymodbus requests pyserial   # 按需：Modbus 用 pymodbus，HTTP 用 requests，串口用 pyserial
```

| 接口类型     | 先跑测试脚本（验证能读到设备） | 再配置并运行 |
|--------------|------------------------------|--------------|
| **Modbus TCP** | `python scripts/python/test_modbus_tcp.py --host <设备IP>` | 改 `device_gateway.py` 里 `DEVICE_CONFIG`，再 `python scripts/python/device_gateway.py` |
| **HTTP**       | `python scripts/python/test_http_device.py --url <设备API地址>` | 同上，在配置里写 `protocol: "http"` 和 `field_mapping` |
| **串口**       | `python scripts/python/test_serial_port.py --port /dev/cu.xxx --baud 9600` | 在 `device_gateway.py` 里实现 `protocol: "serial"` 并配置端口/波特率 |

下面每种接口的详细步骤见「四、调试不同设备接口」。

---

## 四、调试不同设备接口（串口 / Modbus / HTTP）

采集程序（如 `device_gateway.py`）从设备读数据，再转成 JSON 发 MQTT。下面按接口类型说明如何单独调试「设备 → 采集程序」这一段。

### 4.1 串口（Serial）

**第二步·串口**：先用测试脚本确认能收到数据，再在网关里解析并发 MQTT。

1. **用测试脚本验证（不接 MQTT）**
   ```bash
   # 安装依赖
   pip install pyserial
   # Mac 查端口
   ls /dev/cu.*
   # 读 5 行（按实际设备改端口和波特率）
   python scripts/python/test_serial_port.py --port /dev/cu.usbserial-xxx --baud 9600 --lines 5
   ```
   能稳定看到输出，说明串口和波特率正确。

2. **确认端口与权限**
   - Mac: `ls /dev/tty.usb*` 或 `ls /dev/cu.*`
   - Linux: `ls /dev/ttyUSB*` 或 `ls /dev/ttyS*`
   - 权限: `sudo chmod 666 /dev/ttyUSB0`（按实际设备名改）

2. **用 Python 做最小测试**
   ```python
   import serial
   ser = serial.Serial("/dev/ttyUSB0", 9600)  # 波特率按设备说明书
   while True:
       line = ser.readline()  # 或 read(字节数)
       print(line)
   ```
   看是否有稳定、可识别的数据（例如一行一个数、或固定协议帧）。

3. **解析成字段再发 MQTT**
   - 根据设备协议（说明书或厂家示例）从 `line` 或 `read(n)` 里解析出：电压、电流、功率、电量等。
   - 组成本项目约定的 JSON（见 [真实设备接入指南](./真实设备接入指南.md)），用 `paho-mqtt` 发到 `mine/telemetry`。
   - 若 `device_gateway.py` 里已有 `protocol: "serial"`，在对应分支里加日志（打印解析出的 dict），再发 MQTT，便于对比后端是否收到同样内容。

4. **常用工具（可选）**
   - 串口助手、minicom、screen：只做「收发包」验证，不做 JSON。
   - 调试通过后，把解析逻辑放进 `device_gateway.py` 的串口分支即可。

### 4.2 Modbus TCP

**第二步·Modbus TCP**：先用测试脚本读寄存器，再把地址填进 `device_gateway.py`。

1. **用测试脚本验证（不接 MQTT）**
   ```bash
   pip install pymodbus
   # 读一次寄存器（IP/端口/从站/地址按设备手册改）
   python scripts/python/test_modbus_tcp.py --host 192.168.1.100 --port 502 --slave 1 --addr 0 --count 4
   ```
   能打印出 `原始寄存器值` 说明网络和从站/地址正确。

2. **网络与端口**
   ```bash
   ping 192.168.1.100
   nc -zv 192.168.1.100 502   # 或 telnet
   ```

2. **用 Python 读单个寄存器**
   ```python
   from pymodbus.client import ModbusTcpClient
   c = ModbusTcpClient("192.168.1.100", port=502)
   c.connect()
   r = c.read_holding_registers(address=0, count=2, slave=1)  # 地址、从站号按设备手册
   print(r.registers)
   c.close()
   ```
   能读到数再根据设备手册的「寄存器表」确定：哪个地址是电压、电流、功率、电量，以及数据类型（float32 / uint16 等）。

3. **和 device_gateway 配置对应**
   - 在 `device_gateway.py` 的 `DEVICE_CONFIG` 里填好 `host`、`port`、`slave_id`、`registers`（地址与类型）。
   - 先只配一个设备、少量寄存器，运行 `python scripts/python/device_gateway.py`，看打印的 `sensor_data` 是否合理，再在前端/后端确认是否收到对应设备的数据。

4. **工具（可选）**
   - Modbus Poll / Modbus Slave（Windows）、或开源 Modbus 调试工具：连上设备后手动读寄存器，确认地址和值，再把这些地址填进 `device_gateway.py`。

### 4.3 Modbus RTU（串口上的 Modbus）

- 物理层是串口，先按「4.1 串口」确认端口、波特率、能收发。
- 再用 `pymodbus` 的 RTU 客户端（走串口）读寄存器，逻辑同 Modbus TCP，只是把 `ModbusTcpClient` 换成 RTU  over 串口。
- 在 `device_gateway.py` 里若有 `protocol: "modbus_rtu"`，在对应实现里打日志，确认读到的寄存器值，再组 JSON 发 MQTT。

### 4.4 HTTP API

**第二步·HTTP**：先用测试脚本或 curl 拿到设备返回的 JSON，再在网关里做字段映射。

1. **用测试脚本或 curl 看原始响应**
   ```bash
   pip install requests
   python scripts/python/test_http_device.py --url "http://192.168.1.101/api/data"
   ```
   或直接用 `curl -s "http://192.168.1.101/api/data"`。确认返回的是 JSON，并记下字段名（如 `flowRate`、`totalVolume`）。

2. **在 device_gateway 里做字段映射**
   - 在 `DEVICE_CONFIG` 的 `field_mapping` 里把设备字段名映射到本项目字段名，例如：
     - `flowRate` → `flow_rate`
     - `totalVolume` → `consumption`
   - 运行网关脚本，打印解析后的 `data`，确认包含 `consumption`、`flow_rate` 等，再发 MQTT。

3. **校验后端**
   - 用「二」里的方法订阅 MQTT 或看后端日志，确认收到的 JSON 里包含这些字段，且前端有对应设备数据。

## 五、如何保证设备“能向程序发送 JSON”

设备本身通常不会直接发 JSON，而是：

- **情况 A**：设备带 MQTT 客户端，且能配置成按我们的主题和 JSON 格式发布 → 只需在设备侧配置主题为 `mine/telemetry`、payload 为约定 JSON；调试用「二」的脚本或 `mosquitto_sub` 验证即可。
- **情况 B**：设备是串口/Modbus/HTTP 等 → 需要**采集程序**（本机的 `device_gateway.py` 或你自己写的脚本）从设备读数据，转成 JSON 再发 MQTT。  
  - “保证能发 JSON” = 保证这段采集程序：  
    ① 能稳定连上设备并读到数据；  
    ② 解析正确；  
    ③ 用 `paho-mqtt` 发到 `mine/telemetry` 且格式符合 [真实设备接入指南](./真实设备接入指南.md)。

因此：

1. **先不接真实设备**：用 `mqtt_send_test.py` 或 `mosquitto_pub` 发 JSON，确认后端、前端整条链路正常（即插即用、入库、推送）。
2. **再接设备**：按接口类型用上面「三」的方法单独调通「设备 → 采集程序」，最后在采集程序里统一转成同一 JSON 格式发 MQTT，即可保证程序能收到设备数据。

## 六、常见问题速查

| 现象 | 可能原因 | 建议 |
|------|----------|------|
| 前端没有新设备/数据 | 后端没收到 MQTT 或 JSON 格式不对 | 用 2.1 / 2.2 发一条，看后端日志；用 2.3 订阅主题看是否有消息 |
| 串口读不到数据 | 端口号、波特率、校验位不对 | 对照设备手册；用串口助手先确认能收到原始字节 |
| Modbus 读失败 | 从站号、寄存器地址、数据类型不对 | 用 3.2 最小脚本读一两个寄存器；对照设备寄存器表 |
| HTTP 返回 401/404 | 地址或鉴权不对 | 用 curl 带鉴权试一次；检查 `device_gateway.py` 里 URL 和 headers |
| 自动创建设备名称是「设备-xxx」 | 未在 MQTT 里带 `device_name` / `name` | 发 JSON 时加上 `"device_name":"显示名"` 或用 `mqtt_send_test.py --name "显示名"` |

---

## 七、小结

1. **先验证 MQTT → 后端**：用 `python scripts/python/mqtt_send_test.py` 或 `mosquitto_pub` 发 JSON，看后端日志和前端是否出现设备与数据。  
2. **再按接口类型调试设备侧**：串口（看端口与原始字节）、Modbus（看地址与寄存器）、HTTP（看 URL 与字段映射）。  
3. **保证“设备向程序发 JSON”**：要么设备直连 MQTT 并按约定格式发，要么用采集程序从设备读数据、转成约定 JSON 再发 MQTT；两种方式都可用同一套「二」中的方法做接收与调试。
