# 工控设备常用通讯方式详解

> 能源监控、电表、传感器、PLC 等工控场景里常见的通讯方式：物理层、协议、典型设备、优缺点及在本项目中的对应关系。

---

## 一、总览：按「介质」和「协议」分

工控通讯可以分两层看：

- **物理/链路层**：信号在什么介质上跑（串口线、双绞线、无线等）、电平与接口（RS-232/485、以太网、4–20mA 等）。
- **应用/协议层**：数据格式与含义（Modbus、MQTT、OPC、私有协议等）。

同一种物理层可以跑多种协议（例如 RS-485 上跑 Modbus RTU、私有协议）；同一种协议也可以在不同物理层上跑（例如 Modbus 既有 RTU 串口版也有 TCP 网络版）。下面按「常见组合」来介绍几种**最常用**的工控设备通讯方式。

---

## 二、串口类：RS-232 / RS-485

### 2.1 是什么

- **RS-232**：点对点、全双工，用 ±12V 左右电平，常见 DB9 接口，传输距离短（十几米级），多用于电脑与单台设备直连（如老式 PLC 编程口、部分仪表）。
- **RS-485**：差分信号、半双工，用 A/B 两根线，可挂多台设备（总线），抗干扰好、距离可达百米以上，工业现场最常用的**有线串行**方式之一。

串口只规定「怎么传 0/1」，不规定「这些字节代表什么」；上面还要跑**协议**（如 Modbus RTU、自定义文本/二进制）。  
入门与精通可参考：[串口通信入门](./串口通信入门.md)、[串口通信精通版](./串口通信精通版.md)。

### 2.2 典型设备与场景

- 电表、水表、气表（尤其老型号、无网口）
- 温湿度传感器、压力变送器（带 RS-485 输出）
- PLC 的串口编程/通讯口
- 变频器、软启的串口控制口

### 2.3 优缺点（简要）

| 优点 | 缺点 |
|------|------|
| 接线简单（2 线 485 或 3 线 232）、成本低 | 需单独布线，不能直接进办公网 |
| 工业环境成熟、抗干扰（尤其 485） | 速率一般（常用 9600～115200 baud） |
| 大量现成设备支持 | 多设备时需做地址与主从轮询 |

### 2.4 在本项目中的对应

- **采集方式**：网关程序（如 `device_gateway.py`）通过 **USB 转 RS-232/RS-485** 连接设备，按设备协议（如 Modbus RTU）读数据，再转成 JSON 发 **MQTT** 给后端。
- **调试**：先用 `test_serial_port.py` 确认能收到数据，再按协议解析并配置网关。

## 三、Modbus（RTU / TCP）

### 3.1 是什么

**Modbus** 是一套**主从问答**的应用层协议，规定了「从站地址、功能码、寄存器地址、数据、校验」等，不规定物理层。常见两种：

- **Modbus RTU**：跑在**串口**上（RS-232/RS-485），一帧为二进制，帧尾 CRC-16；从站地址 1～247。
- **Modbus TCP**：跑在 **TCP/IP** 上，把「从站地址」等放进 TCP 载荷，无 CRC（依赖 TCP）；常用端口 502。

寄存器是「从机里的一小块数据」：保持寄存器（可读可写）、输入寄存器（只读）等，电表常把电压、电流、功率、电量放在固定地址，手册会给出「寄存器表」。

### 3.2 典型设备与场景

- 智能电表、电能表（几乎标配 Modbus）
- 电力监控装置、配电监控
- 部分水表、热表、冷表（Modbus 寄存器输出）
- PLC、触摸屏（作从站或主站）

### 3.3 优缺点（简要）

| 优点 | 缺点 |
|------|------|
| 协议公开、实现多、工具多（Modbus Poll 等） | 主从轮询，实时性受轮询周期限制 |
| 寄存器模型简单，易映射到「点表」 | 无安全、无加密，多用于内网 |
| RTU 省线（485 总线），TCP 易接入现有网络 | 大数据量、高频采集不如专用工业以太网 |

### 3.4 在本项目中的对应

- **Modbus TCP**：`test_modbus_tcp.py` 做单次读寄存器测试；`device_gateway.py` 里 `protocol: "modbus_tcp"`，配置 `host/port/slave_id/registers`，周期读寄存器并发 MQTT。
- **Modbus RTU**：若设备是串口 485，网关用 `protocol: "modbus_rtu"`，通过串口发 Modbus 帧，逻辑与 TCP 版类似（同一套寄存器表），只是收发走串口。

## 四、以太网 / TCP-IP（含 Modbus TCP、HTTP、OPC）

### 4.1 是什么

设备带**网口**，通过 **TCP/IP** 与上位机或网关通讯；应用层可以是：

- **Modbus TCP**：同上，端口 502，适合电表、配电监控等。
- **HTTP/HTTPS**：设备提供 REST API，返回 JSON/XML；网关用 `requests` 等轮询或设备主动推送。
- **OPC / OPC UA**：工业通用数据交换标准，多用于 DCS/SCADA 与 PLC、仪表互联；OPC UA 支持加密、发现、复杂数据类型。

这里把「以太网」作为**物理/传输层**，上面再选一种**应用协议**。

### 4.2 典型设备与场景

- 带网口的智能电表、能源网关
- 工业触摸屏、HMI（通过 Modbus TCP 或 OPC 与 PLC 通讯）
- 云平台型传感器（HTTP API 上报）
- 工厂/楼宇 SCADA、DCS（OPC UA 汇聚各子系统）

### 4.3 优缺点（简要）

| 优点 | 缺点 |
|------|------|
| 可直接走现有局域网/光纤，无需单独串口线 | 设备需带网口，成本略高 |
| 可远程、可集中监控、易与 IT 系统集成 | 需考虑 IP、防火墙、网段规划 |
| Modbus TCP / HTTP 易于在 PC/网关用脚本实现 | 工业现场部分环境仍偏好 485（无交换机） |

### 4.4 在本项目中的对应

- **Modbus TCP**：见上；`device_gateway.py` 的 `read_modbus_tcp()`。
- **HTTP**：`device_gateway.py` 里 `protocol: "http"`，配置 `url`、`field_mapping`，用 `requests` 取数据后组 JSON 发 MQTT；`test_http_device.py` 可先验证 URL 与返回字段。

## 五、MQTT（物联网常用）

### 5.1 是什么

**MQTT** 是**发布/订阅**的轻量消息协议，跑在 **TCP** 上；设备或网关向 **Broker** 发布消息，订阅者从 Broker 收消息。主题（Topic）用于区分不同类型数据（如 `campus/telemetry` 表示遥测）。

- 适合设备多、上行数据以「事件/遥测」为主的场景；  
- 本项目里：设备或**采集网关**把数据发到 MQTT → **后端**订阅同一主题 → 入库、报警、再通过 WebSocket 推前端。

### 5.2 典型设备与场景

- 自带 MQTT 的智能电表、物联网网关
- 云边协同：边缘网关采集串口/Modbus，转成 JSON 发 MQTT，云端统一处理
- 本系统：模拟器、真实设备（经网关）都通过 MQTT 上报

### 5.3 优缺点（简要）

| 优点 | 缺点 |
|------|------|
| 轻量、易嵌入、支持 QoS、适合弱网 | 需部署 Broker（如 Mosquitto） |
| 发布/订阅解耦，多订阅者方便 | 实时性依赖 Broker 与网络，非硬实时 |
| 与云平台、后端集成简单 | 工业现场不少老设备仍以 Modbus/串口为主 |

### 5.4 在本项目中的对应

- **后端**订阅 `campus/telemetry`（及 `campus/device/+/telemetry`），收到 JSON 后写库、报警、WebSocket 推送。
- **设备侧**：要么设备直连 MQTT 并按约定 JSON 格式发布；要么由 **device_gateway** 从串口/Modbus/HTTP 读数据，转成同一 JSON 格式再发 MQTT。

## 六、4–20mA / 0–10V（模拟量，非数字通讯）

### 6.1 是什么

这不是「数字通讯协议」，而是**模拟信号**接口：

- **4–20mA**：电流环，4 mA 通常表示量程下限（或故障），20 mA 表示上限；抗干扰好、可长距离，工业传感器非常常用。
- **0–10V**：电压信号，0 V 对应下限，10 V 对应上限；接线简单，但长距离易受压降和干扰影响。

需要**采集卡/PLC 模拟量输入（AI）**或**带模拟量输入的网关**把电流/电压转换成数字量，再通过 Modbus/网络等方式传给上位机。

### 6.2 典型设备与场景

- 压力、温度、流量、液位变送器（输出 4–20mA）
- 变频器频率给定、阀门开度（0–10V 控制）
- 老式仪表无数字接口，仅模拟输出

### 6.3 优缺点（简要）

| 优点 | 缺点 |
|------|------|
| 接线简单、标准化、抗干扰（4–20mA） | 一根线一般只传一个量，无地址、无协议 |
| 大量传感器、执行器支持 | 需 AD 采集，精度和分辨率受采集卡限制 |
| 故障可借「4 mA 断线」等判断 | 无法直接进电脑串口/网口，需中间采集设备 |

### 6.4 与本项目的关系

- 若设备**只有** 4–20mA 输出：需用带 AI 的 PLC 或采集模块，由该设备通过 **Modbus/网络** 把转换后的数字值上传；本系统侧仍通过 Modbus TCP/RTU 或 MQTT 与采集设备对接，不直接接 4–20mA。

## 七、其他常见方式（简要）

### 7.1 Profibus / Profinet

- **Profibus**：基于 RS-485 或专用线缆的现场总线，西门子等 PLC 常用，主从结构，协议较复杂。
- **Profinet**：基于以太网，实时扩展，用于 PLC、驱动、IO 等。
- **与本项目**：若现场是 Profibus/Profinet，通常由 PLC 或网关做协议转换，再以 Modbus TCP/OPC 等方式把数据送到本系统，本系统不直接接 Profibus/Profinet。

### 7.2 CAN / CANopen

- **CAN**：多主、差分、多用于汽车和部分工业（如伺服、变频器）。
- **CANopen**：在 CAN 上的应用层协议，有对象字典、PDO/SDO 等。
- **与本项目**：设备若只有 CAN，需 **CAN 转串口/以太网** 或网关，再由网关以 Modbus/MQTT 等形式接入本系统。

### 7.3 OPC / OPC UA

- **OPC DA**（老）：基于 Windows COM，多用于 Windows 上位机与 PLC/仪表对接。
- **OPC UA**：跨平台、可加密、支持复杂类型与发现机制，越来越多 DCS/SCADA 和云平台采用。
- **与本项目**：若已有 OPC UA 服务器（如从 PLC 或第三方网关暴露），可写一个** OPC UA 客户端**脚本，订阅/轮询点位，转成 JSON 发 MQTT，与现有后端对接。

### 7.4 国标 DL/T 645（电表）

- 中国**电能表**常用通讯规约，有 1997 版和 2007 版；多跑在 **RS-485** 上，帧格式与 Modbus 不同（有前缀、地址、控制码、数据域、校验等）。
- **与本项目**：若电表只支持 645，需在网关里实现 **DL/T 645 解析**（或使用现成库），读出的数据再组成本系统约定的 JSON 发 MQTT。

## 九、小结

- **串口（RS-232/485）**：工控最基础的有线方式，上面跑 Modbus RTU 或私有协议；本项目用网关串口读设备再发 MQTT。
- **Modbus（RTU/TCP）**：电表、配电、仪表最常见；本项目已支持 Modbus TCP 和网关内 Modbus RTU。
- **以太网（Modbus TCP、HTTP、OPC UA）**：便于接入现有网络和 IT 系统；本项目通过网关或直连 MQTT 对接。
- **MQTT**：本系统的「设备数据入口」，设备或网关统一发 MQTT，后端统一处理。
- **4–20mA/0–10V**：模拟量，需经采集设备转数字后再用数字通讯接入。
- **Profibus/CAN/OPC/DL/T 645**：按现场已有设备选；本项目侧通常通过「网关或转换器」变成 Modbus/MQTT 再接入。

实际选型时：先看**设备本身支持哪种**（手册会写），再决定是用本项目现有网关（串口/Modbus TCP/HTTP）直接接，还是加一层协议转换（如 645 解析、OPC 客户端）再发 MQTT。
