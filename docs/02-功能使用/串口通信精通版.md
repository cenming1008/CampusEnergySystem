---

## 一、UART 与串口：芯片层 vs 电气层

### 1.1 概念区分

- **UART**（Universal Asynchronous Receiver/Transmitter）：芯片内部的**异步收发器**，负责：
  - 把并行字节变成**串行位流**发出去；
  - 把串行位流**采样、还原成字节**收进来；
  - 不规定电压和接口形状，只规定「怎么把 0/1 按时序发出去」。
- **串口**（Serial Port）：我们常说的「串口」= **UART + 物理接口与电平**。  
  例如：电脑的 DB9「COM 口」= UART + RS-232 电平；工业模块的 A/B 端子 = UART + RS-485 收发器。

所以：**协议和帧格式在 UART 之上；UART 之上还有应用层协议（Modbus、自定义等）**。

### 1.2 异步与「位时间」

- **异步**：没有单独的时钟线，收发双方各自用**本地时钟**，靠**起始位**对齐每一帧的起点。
- **位时间**：每个 bit 持续的时间 = 1 / 波特率。例如 9600 baud → 一位约 104 μs。
- **采样**：接收端通常在**每位中间**采样一次（或多次取多数），所以双方波特率不能差太多（常见要求 ±2% 以内），否则长期会错位、出现乱码或帧错误。

## 二、流控（Flow Control）

当接收方处理不过来时，需要一种方式让发送方「停一停」，否则缓冲区溢出会丢数据。

### 2.1 无流控（None）

- 最常见：不接任何流控线，发送方一直发，接收方能收多少算多少。
- 适用：设备主动上报、速率不高，或协议里自带「请求-应答」节奏（如 Modbus 一问一答）。

### 2.2 硬件流控：RTS/CTS

- **RTS**（Request To Send）：本机「我要发」；**CTS**（Clear To Send）：对方「你可以发」。
- 需要**多接两根线**（RTS、CTS），且双方都支持。  
  发送前拉 RTS，对方若准备好会拉 CTS；若对方不拉 CTS，本机应暂停发送。
- 在 pyserial 里：`ser = serial.Serial(port, baud, rtscts=True)`。

### 2.3 软件流控：XON/XOFF

- 用两个**特殊字符**：收到 XON（0x11）允许发，收到 XOFF（0x13）暂停发。
- 缺点：若数据里本身包含 0x11/0x13 会误触发，二进制协议一般不采用；**仅适合纯文本**。
- pyserial：`ser = serial.Serial(port, baud, xonxoff=True)`。

**实际建议**：工业设备多数为无流控或硬件流控；做网关时先无流控，若出现缓冲区满再考虑 RTS/CTS 或降低发送频率。

## 三、帧同步与边界：字节流 vs 应用帧

串口给你的是**连续字节流**，没有「第几帧」的标记。应用层需要自己**划清一帧的边界**。

### 3.1 常见定界方式

| 方式 | 说明 | 适用 |
|------|------|------|
| **固定长度** | 每帧 N 字节，读满 N 即一帧 | 协议简单、长度固定 |
| **长度前缀** | 前 1～2 字节表示本帧长度，再读后续字节 | 二进制协议常用 |
| **结束符** | 以 `\r\n` 或 `0x0D 0x0A` 等为结尾，读到即一帧 | 文本协议、AT 指令 |
| **超时定界** | 连续一段时间（如 3.5 个字符时间）无新数据，认为一帧结束 | Modbus RTU 的帧间间隔 |
| **特殊头尾** | 如 0xAA 0x55 开头、校验和结尾，解析时找头、算长、校验 | 自定义二进制 |

### 3.2 粘包与半包

- **粘包**：多帧数据在缓冲里连在一起，一次 `read()` 拿到多帧，需要按上面定界方式**拆帧**。
- **半包**：一帧还没收完就去做 `read()`，只拿到半帧，需要**缓冲拼接**，凑满一帧再解析。

因此**稳健做法**是：维护一个**接收缓冲区**，每次 `read()` 把新数据追加进去，再用**状态机**或**循环**按「长度前缀 / 结束符 / 超时」切出一帧一帧处理。

### 3.3 Modbus RTU 的帧间间隔

- Modbus RTU 规定：两帧之间至少间隔 **3.5 个字符时间**（无数据）。  
  字符时间 = 1 帧的位数 / 波特率（如 11 位/字符时，3.5 字符 ≈ 4 ms @ 9600）。
- 从站用这段「静默」判断上一帧结束；主站发下一帧前要保证静默时间，否则从站可能误判帧边界。

## 四、多字节数据与字节序（Endianness）

协议里经常有「2 字节表示一个数」「4 字节 float」等，必须约定**谁在前谁在后**。

### 4.1 大端 vs 小端

- **大端（Big-Endian）**：**高字节在前**（先发/先存）。例如 0x1234 → 线上顺序 `12 34`。  
  网络字节序、很多工业协议（含 Modbus）默认大端。
- **小端（Little-Endian）**：**低字节在前**。0x1234 → `34 12`。  
  x86、很多单片机内存是小端。

设备手册里会写「高字节在前」或「Low byte first」等，解析时必须一致。

### 4.2 在 Python 里解析多字节

```python
import struct

# 从 bytes 解析（buf 为 bytes）
# 2 字节无符号大端
val_uint16_be = struct.unpack(">H", buf[0:2])[0]   # > = 大端, H = uint16

# 2 字节有符号大端
val_int16_be = struct.unpack(">h", buf[0:2])[0]   # h = int16

# 4 字节 float 大端（如 Modbus 里两个寄存器拼一个 float32）
val_float_be = struct.unpack(">f", buf[0:4])[0]    # f = float32

# 小端用 <
val_uint16_le = struct.unpack("<H", buf[0:2])[0]
val_float_le  = struct.unpack("<f", buf[0:4])[0]
```

**Modbus 里 float32**：通常占 2 个寄存器（4 字节），有的设备「高字在前、高字节在前」即大端；有的「高字在后」或「字内小端」，需按手册选 `struct` 的格式或调字节顺序。

## 五、校验与 CRC

### 5.1 奇偶校验的局限

- 串口参数里的奇/偶校验只能发现**奇数个位错误**，且无法纠错；一个帧里错 2 位可能校验仍「正确」。
- 工业协议几乎都会在**应用层**再做一层校验：**CRC 或校验和**。

### 5.2 CRC-16（如 Modbus）

- Modbus RTU 帧尾是 **CRC-16**（多项式等见 Modbus 规范），覆盖从「从站地址」到「数据」的所有字节。
- 接收方重算 CRC，与帧尾两字节比较；不一致则**整帧丢弃**，不响应（主站可重发）。
- Python：可用 `struct` 自己实现，或使用 `pymodbus` 里现成的 CRC 计算。

### 5.3 校验和（Checksum）

- 简单做法：所有字节相加取低 8 位（或 16 位），放在帧尾。  
  比 CRC 弱，但实现简单，很多简单自定义协议用这个。

## 六、RS-485 深入：半双工与多从站

### 6.1 差分与抗干扰

- RS-485 用**两根线 A/B** 的**电压差**表示 0/1，共模噪声对两根线影响相近，差分后抵消，因此抗干扰、可长距离（可达百米级，视速率而定）。
- 逻辑「1」：A > B；逻辑「0」：A < B（具体电压范围见标准）。

### 6.2 半双工与收发切换

- **半双工**：同一时刻只有一方在发，总线是「要么主发从收，要么从发主收」。
- 硬件上收发器有 **DE（Driver Enable）/ RE（Receiver Enable）**：  
  - 发数据前：DE=1、RE=0（或合并为一根 R/D）；  
  - 发完后：DE=0、RE=1，切回接收，等从站应答。  
- 若用 USB 转 RS-485 模块，有的模块**自动切换**（根据发完自动切收），有的需软件控制 R/D 脚（通过 pyserial 的 RTS 等模拟）。

### 6.3 多从站与总线拓扑

- 多台设备**并接**在 A、B 两根总线上，每台有唯一**从站地址**。
- 主站发一帧（帧内含从站地址），只有地址匹配的从站应答，其余从站不应答。  
  因此**一帧内必须含地址**，且主站发完要切回接收、等足够时间再发下一帧。
- **终端电阻**：长距离时在总线**两端**各加 120Ω 电阻，减少反射，提高稳定性。

### 6.4 与 Modbus RTU 的关系

- Modbus RTU 跑在 RS-485 上时，就是「主站发请求（带从站地址）→ 静默 → 从站答」；  
  帧间 3.5 字符静默、CRC 校验，前面已述。

## 七、缓冲、超时与健壮读

### 7.1 缓冲层次

- **硬件/驱动缓冲**：内核为串口设备维护输入/输出缓冲，`read()` 是从这里取。
- **pyserial**：`ser.in_waiting` 表示当前**可读字节数**，可根据协议「凑够一帧再读」或「按超时读」。

### 7.2 阻塞、非阻塞与超时

- **timeout=0**：非阻塞，`read()` 立刻返回，有则返回已有数据，无则返回空。
- **timeout>0**：阻塞最多 N 秒，期间有数据就返回（可能少于请求的字节数），超时则返回已读到的。
- **timeout=None**：一直等到读满请求的字节数（或到 EOF），慎用，容易卡死。

建议：**设一个合理 timeout**（如 0.5～2 秒），在循环里读，用「超时定界」或「长度+超时」组帧。

### 7.3 按帧读的示例思路（状态机）

```python
# 伪代码：长度前缀帧（前 2 字节大端表示长度）
buf = b""
while True:
    chunk = ser.read(ser.in_waiting or 1)  # 有则读，无则至少等 1 字节
    if not chunk and timeout:
        break
    buf += chunk
    while len(buf) >= 2:
        length = struct.unpack(">H", buf[0:2])[0]
        if len(buf) < 2 + length:
            break
        frame = buf[2 : 2 + length]
        buf = buf[2 + length :]
        # 校验、解析 frame
        process(frame)
```

实际要按你的协议改：长度占几字节、是否含校验、是否大端等。

### 7.4 写超时（write_timeout）

- 写时若对方不收、驱动缓冲满，写会阻塞；设 `write_timeout` 可避免无限等。  
  例如 `serial.Serial(port, baud, timeout=1, write_timeout=1)`。

## 八、常见问题与调试

### 8.1 乱码

- **波特率/数据位/停止位/校验** 任一项不一致都会乱码，逐项对照设备手册。
- **时钟误差**：双方晶振误差叠加后若超约 ±2%，可能偶发错位，可尝试略降波特率或换设备验证。

### 8.2 丢字节 / 错帧

- 接收缓冲满：提高读频率、用线程专门读、或开流控。
- 帧定界错误：检查是否按「长度前缀/结束符/超时」正确切帧，有无粘包半包。
- 多线程/多进程抢同一串口：同一时间只应有一个进程打开并读写一个串口。

### 8.3 调试手段

- **十六进制打印**：收到数据先 `print(buf.hex())` 或每字节 `%02X`，对照协议文档看是否与预期一致。
- **串口抓包/监听**：若有两路串口（如 USB 转双路），可一路接设备、一路接「监听器」抓双向数据；或使用带「环回」的硬件。
- **逻辑分析仪**：抓 TX/RX 波形，看起始位、数据位、停止位是否与设定一致，波特率是否准确。

### 8.4 接地与共模

- 两端 GND 要共地，否则可能收不到或误码。  
- 长距离或强干扰场合考虑**隔离**（隔离型 USB 转 485、光耦等），避免地环路和共模电压损坏设备。

## 九、工业常见串口协议概览

### 9.1 Modbus RTU 帧结构（复习）

- 一帧：**从站地址(1) + 功能码(1) + 数据(N) + CRC(2)**。  
  主站发请求，从站回响应（响应里也是 地址+功能码+数据+CRC）。  
- 功能码 03：读保持寄存器；04：读输入寄存器。  
- 地址、寄存器号多为**大端**；CRC 为小端（低字节在前）存放。

### 9.2 自定义二进制帧示例

例如：**0xAA 0x55 [长度 1 字节] [数据] [校验和 1 字节]**。

- 接收端：先找 `AA 55`，再读长度，再读「长度」个字节 + 1 字节校验和；校验通过再解析数据区。

### 9.3 文本协议（行式）

- 每行以 `\r\n` 或 `\n` 结尾，用 `readline()` 即可。  
- 注意：有的设备只发 `\r`，需在解析时统一处理（strip `\r\n`），并注意编码（UTF-8 / GBK）。

## 十、与本项目结合：网关侧建议

### 10.1 device_gateway.py 串口分支

- **打开参数**：与设备手册一致（波特率、8N1、必要时 RTS/CTS），并设 `timeout`、`write_timeout`。
- **读**：按设备协议做**定界**（行、长度前缀或超时），再解析出电压、电流等字段，组成本项目约定的 JSON。
- **写**：若需下发指令（如 Modbus 请求），发完后根据协议等待响应再解析，避免把「请求」和「响应」混在一个缓冲里当一帧。

### 10.2 健壮性

- **重连**：串口打开失败或多次读超时，可关闭再打开、带退避重试。
- **日志**：关键步骤打日志（打开成功、每帧原始 hex、解析出的字段、发送 MQTT 成功），便于线上排查。
- **异常**：捕获串口异常（如设备拔掉），避免进程直接退出，可重连或告警。

### 10.3 与 test_serial_port.py 的配合

- 先用 `test_serial_port.py` 确认**能稳定收到原始数据**；  
  再根据设备协议在网关里实现**同一套**定界与解析逻辑，并发 MQTT。  
  调试时可在网关里把「原始 hex」和「解析结果」都打出来，与文档对照。

## 十一、精通版小结

| 主题 | 要点 |
|------|------|
| UART vs 串口 | UART 是芯片层异步收发；串口 = UART + 电平（TTL/232/485）。 |
| 流控 | 无 / 硬件 RTS-CTS / 软件 XON-XOFF；工业常用无或硬件。 |
| 帧同步 | 定长、长度前缀、结束符、超时定界；注意粘包半包与缓冲状态机。 |
| 字节序 | 大端/小端与多字节解析；用 `struct.unpack` 与设备手册一致。 |
| 校验 | 奇偶仅作参考；应用层用 CRC-16 或校验和。 |
| RS-485 | 差分、半双工、收发切换、多从站地址、帧间静默、终端电阻。 |
| 缓冲与超时 | in_waiting、timeout、按帧读、write_timeout。 |
| 调试 | 十六进制打印、抓包、逻辑分析仪、接地与隔离。 |

把入门版的「能通」和精通版的「帧、序、校验、流控、485、健壮读」结合起来，就能在工业串口场景里独立设计和排障。
