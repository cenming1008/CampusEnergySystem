# 数据清理功能详细说明

## 📋 清除数据功能说明

前端页面上的 **"清理 X 小时前的数据"** 按钮会清除以下数据：

---

## 🗑️ 清除的数据类型

### 1. **时序数据（EnergyData）** ⚡

**表名**：`energydata`

**清除内容**：
- ✅ 所有设备的能源数据记录
- ✅ 包括：电力、水、气、热、冷等多种能源类型
- ✅ 字段包括：累计消耗量、瞬时流量/功率、电压、电流等

**清除条件**：
- `timestamp < (当前时间 - 指定小时数)`
- 例如：清理"1小时前"的数据，会删除所有 `timestamp < 1小时前` 的记录

**影响**：
- ⚠️ **会删除历史能源消耗数据**
- ⚠️ **影响历史趋势图表**
- ⚠️ **影响能耗分析和报表**

---

### 2. **报警记录（Alarm）** 🚨

**表名**：`alarm`

**清除内容**：
- ✅ **只清理已解决的报警记录**
- ✅ 未解决的报警**不会被删除**（安全保护）

**清除条件**：
- `timestamp < (当前时间 - 指定小时数)`
- **且** `is_resolved = true`（已解决）

**影响**：
- ⚠️ **会删除历史报警记录**
- ✅ **未解决的报警不受影响**（重要！）
- ⚠️ **影响报警历史查询**

---

### 3. **碳排放记录（CarbonEmission）** 🌱

**表名**：`carbon_emission`

**清除内容**：
- ✅ 所有设备的碳排放记录
- ✅ 包括：碳排放量、碳排放因子等

**清除条件**：
- `timestamp < (当前时间 - 指定小时数)`

**影响**：
- ⚠️ **会删除历史碳排放数据**
- ⚠️ **影响碳排放统计和分析**

---

## ❌ **不会清除的数据**

以下数据**不会被清除**，请放心：

### ✅ 基础数据（永久保留）
- **设备信息**（Device 表）
- **用户信息**（User 表）
- **位置信息**（Location 表）
- **设备分组**（DeviceGroup 表）
- **维护记录**（DeviceMaintenance 表）

### ✅ 统计数据（有独立的保留策略）
- **能源统计**（EnergyStatistics 表）
  - 自动清理保留期：365天
  - 手动清理：不包含在此功能中

### ✅ 未解决的报警（安全保护）
- **未解决的报警记录**不会被删除
- 只有 `is_resolved = true` 的报警才会被清理

---

## 📊 清理示例

### 示例1：清理"1小时前"的数据

**操作**：点击"清理 1 小时前的数据"按钮

**清除内容**：
- 所有 `timestamp < 1小时前` 的 EnergyData 记录
- 所有 `timestamp < 1小时前` 且 `is_resolved = true` 的 Alarm 记录
- 所有 `timestamp < 1小时前` 的 CarbonEmission 记录

**保留内容**：
- 最近1小时内的所有数据
- 所有未解决的报警
- 所有基础数据（设备、用户等）

### 示例2：清理"12小时前"的数据

**操作**：选择"12小时前"，点击清理按钮

**清除内容**：
- 所有 `timestamp < 12小时前` 的 EnergyData 记录
- 所有 `timestamp < 12小时前` 且 `is_resolved = true` 的 Alarm 记录
- 所有 `timestamp < 12小时前` 的 CarbonEmission 记录

**保留内容**：
- 最近12小时内的所有数据
- 所有未解决的报警
- 所有基础数据

---

## ⚠️ 重要提示

### 1. **数据不可恢复**
- ❌ 删除的数据**无法恢复**
- ❌ 没有回收站或撤销功能
- ✅ **建议清理前先备份数据库**

### 2. **影响范围**
- ⚠️ 会影响历史数据查询
- ⚠️ 会影响历史趋势图表
- ⚠️ 会影响历史报表生成

### 3. **安全保护**
- ✅ 未解决的报警不会被删除
- ✅ 基础数据（设备、用户等）不会被删除
- ✅ 统计数据有独立的保留策略

---

## 📝 数据表结构说明

### EnergyData（时序数据表）
```sql
CREATE TABLE energydata (
    device_id INT,
    timestamp TIMESTAMP,
    energy_type VARCHAR,      -- 能源类型：electricity/water/gas/heat等
    consumption FLOAT,        -- 累计消耗量
    flow_rate FLOAT,          -- 瞬时流量/功率
    voltage FLOAT,            -- 电压
    current FLOAT,            -- 电流
    ...
    PRIMARY KEY (device_id, timestamp)
);
```

### Alarm（报警记录表）
```sql
CREATE TABLE alarm (
    id INT PRIMARY KEY,
    device_id INT,
    message VARCHAR,
    timestamp TIMESTAMP,
    is_resolved BOOLEAN,      -- 是否已解决
    ...
);
```

### CarbonEmission（碳排放记录表）
```sql
CREATE TABLE carbon_emission (
    device_id INT,
    timestamp TIMESTAMP,
    energy_type VARCHAR,
    energy_consumption FLOAT,
    carbon_emission FLOAT,    -- 碳排放量
    ...
    PRIMARY KEY (device_id, timestamp)
);
```

## 🎯 使用建议

### ✅ 适合清理的场景：
1. **测试环境**：清理测试数据
2. **存储空间不足**：释放数据库空间
3. **数据迁移前**：清理旧数据
4. **定期维护**：清理过期数据

### ❌ 不建议清理的场景：
1. **生产环境**：除非确定不需要历史数据
2. **数据分析前**：需要历史数据进行趋势分析
3. **审计要求**：需要保留历史记录

---

## 🔄 与自动清理的区别

### 手动清理（前端按钮）
- **时间范围**：1-24小时前
- **执行方式**：手动触发
- **清除内容**：EnergyData、Alarm（已解决）、CarbonEmission

### 自动清理（定时任务）
- **时间范围**：90-365天前（可配置）
- **执行方式**：每天凌晨3点自动执行
- **清除内容**：EnergyData、Alarm（已解决）、CarbonEmission、EnergyStatistics
