## 背景

当前主区已从“位置管理页展示重构专题”退出，等待下一个主主题。用户本轮明确提出“利用 Figma 重新设计告警界面 UI”，当前最直接、最独立且符合园区 EMS 主线的新主题即为告警中心页面的前端重设计。

已确认当前页面入口为：

- `frontend/src/views/AlarmCenter.vue`
- 路由：`/alarms`

已确认当前实现问题主要不在功能缺失，而在信息层级和视觉组织偏弱：

- 页面只有基础标题、筛选条和表格，缺少“当前告警压力”的首屏态势表达
- 活跃告警、高优先级告警、影响设备数等运营判断信息没有首屏聚合
- 筛选与处理动作存在，但后台工作台感不强，列表缺少优先级和处理状态的视觉区分
- 用户后续补充了 Figma 生成版式参考代码，本轮允许吸收其“头部 + 指标 + 趋势 + 控制区 + 列表”的排版结构，但颜色与整体风格继续服从现有项目后台视觉体系，且全部文案统一改为中文。

## 设计收敛结论

### 1. 页面定位

- 本页定位为：`告警工作台 / 告警中心管理页`
- 重点是“筛查、定位、处置”，不是展示型大屏

### 2. 视觉方向

- 继续沿用当前项目的深色控制台基础
- 用更明确的危险色、时间线信息和摘要卡强化告警状态感
- 保持运营后台风格的高密度和高可读性，不做过度装饰

### 3. 信息结构

本轮首屏结构固定为：

1. 顶部告警态势区
2. 摘要指标区
3. 筛选与处置区
4. 告警工作台列表

### 4. 交互边界

- 保留单条处理与批量处理动作
- 保留设备筛选、时间窗筛选、状态筛选和条数控制
- 允许把原“开始/结束时间”收敛为更直观的时间范围控件
