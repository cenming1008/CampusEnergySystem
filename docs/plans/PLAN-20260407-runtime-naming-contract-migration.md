# PLAN-20260407 Runtime Naming Contract Migration

> 状态：五轮验收通过，已阶段收口，暂不迁 archive | 负责人：规范 / 验收线程 | 更新时间：2026-04-08

## 背景

当前仓库产品定位已经收敛到“园区综合能源管理系统 / Campus Energy Management System / 智慧园区 EMS”，但运行时层仍残留 `mine_*` 命名与相关契约。

本轮任务不是用户可见文案迁移，也不属于刚完成阶段收口的 `application use case 分层收口专题`。当前任务属于高风险运行时命名 / 契约迁移，涉及：

1. Docker 可见命名
2. 运行时数据 / 连接契约
3. 观测与联调契约

探索已确认：

- 当前任务必须独立立项
- 不应一次性全文替换
- 整体建议拆成 5 轮
- 第一轮只适合处理 Docker 可见命名与其直接依赖层

## 目标

- 以最小可回滚方式，逐轮把运行时层的 `mine_*` 命名向 `campus_*` 收敛。
- 让每一轮都保持清晰边界、独立验收、独立回滚点。
- 避免把运行时命名迁移误做成一次性全仓替换、全链路契约改造或无边界重构。

## 非目标

- 不做一次性全文替换
- 不做全仓 rename
- 不在第一轮修改数据库名 / `DATABASE_URL`
- 不在第一轮修改 MQTT 用户名 / topic / wildcard
- 不在第一轮修改 Prometheus / Alertmanager / 域名联调契约
- 不借本主题顺手展开 Docker / nginx / scripts 全面重构
- 不修改 `docs/archive/` 与 `docs/plans/daily/` 历史材料

## 第一轮范围

第一轮只处理 Docker 可见命名与其直接依赖层：

- `container_name`
- 直接依赖容器名的脚本
- 直接依赖容器名的文档
- nginx upstream 内部别名

第一轮允许动作：

- 将对外或运维可见的容器名从 `mine_*` 向 `campus_*` 收敛
- 同步修正明确依赖这些容器名的脚本引用
- 同步修正文档中的直接依赖说明
- 调整 nginx upstream 内部别名，只要影响边界仍停留在内部代理和容器互联层

## 后续轮次范围

### 第二轮候选范围

- 运行时数据 / 连接契约的最小收口
- 仅处理内部连接契约与脚本 / 文档依赖口径
- 仅处理已经被探索明确锁定、且能独立验收与独立回滚的连接名收敛

第二轮明确不处理：

- 数据库名本体 `mine_energy`
- `DATABASE_URL`
- 任何需要改动数据库名语义、数据目录、卷名或备份恢复口径的迁移

第二轮执行口径必须区分：

- 仓库代码 / 文档 / 脚本改动
- 本机运行环境切换清理

后者只作为验证风险记录，不属于第二轮交付物。

### 第三轮候选范围

- MQTT 用户名
- MQTT topic
- MQTT wildcard 订阅口径
- 仅限设备联调、worker 订阅、发送脚本与实时链路直接依赖的 MQTT 契约收口

第三轮优先于数据库名本体 / `DATABASE_URL` 的原因：

- MQTT 契约虽然会影响设备联调、worker 订阅、发送脚本与实时链路，但仍可在消息链路层独立验收与独立回滚
- 数据库名本体与 `DATABASE_URL` 会直接牵动数据目录、备份恢复、连接串和本机运行态切换，不适合作为当前下一轮

### 第四轮候选范围

- 数据库名本体 `mine_energy`
- `DATABASE_URL`
- 与数据库命名直接绑定、且必须同轮处理的连接串口径

第四轮最小可控范围只包括：

- 数据库名本体 `mine_energy`
- `DATABASE_URL`
- 代码、脚本、文档中直接依赖数据库名或 `DATABASE_URL` 语义的活跃口径

第四轮执行口径必须区分：

- 仓库改动
- 本机运行环境切换动作
- 回滚动作

第四轮只在满足以下前提时才建议启用：

- 第三轮 MQTT 契约迁移已独立通过
- 已补齐数据库命名迁移的验证与回退方案
- 已明确区分仓库改动与本机运行环境切换动作

### 第五轮候选范围

- Prometheus 指标命名
- Alertmanager / alert expr
- 域名联调口径
- 观测面板与联调访问相关契约

第五轮最小可控范围只包括：

- Prometheus 活跃 `rule group` / `expr` / `job` 命名口径
- Alertmanager 相关活跃联调口径
- 活跃文档中的观测 / 域名联调命名
- 活跃区残留的 `mine_energy_backend`、`mine_mqtt_*` 及其直接相关观测契约

第五轮执行口径必须区分：

- 命名契约收口
- 监控体系重构
- 联调环境重建

其中只有第一项属于第五轮交付物。

## 回滚边界

### 第一轮回滚点

- 容器名、脚本引用、文档口径、nginx upstream 内部别名可整体回退到第一轮前的稳定 `mine_*` 口径
- 若发现依赖链超出第一轮边界，直接整轮回退，不做局部硬撑

### 第二轮回滚点

- 若连接契约迁移导致服务互联失败、启动失败或环境变量引用断裂，整轮回退到第一轮稳定状态
- 若发现某项改动实际上必须连带修改数据库名本体或 `DATABASE_URL` 才能成立，该项立即回退并从第二轮剥离
- 若验证仅受本机旧 `mine_energy_db_dev` 占口、旧容器未停或端口未腾挪影响，记为环境切换风险，不纳入仓库代码回滚判断
- 不允许长期停留在新旧连接名混杂的半状态

### 第三轮回滚点

- 若 MQTT 用户名 / topic / wildcard 迁移导致订阅、发布、告警或实时链路异常，整轮回退到第二轮稳定状态
- 不允许长期双 topic 漫游，除非后续单独立项为兼容窗口策略

### 第四轮回滚点

- 若数据库名本体或 `DATABASE_URL` 迁移导致连接失败、数据目录错配、备份恢复链路失真或本机切换态混乱，整轮回退到第三轮稳定状态
- 若验证仅受本机旧 `mine_energy_db_dev` 占口、旧容器未停或端口未腾挪影响，记为环境切换风险，不纳入仓库代码回滚判断
- 若某项数据库命名改动必须连带修改数据目录、卷名、备份恢复口径或监控联调契约才能成立，该项立即回退并从第四轮剥离
- 不允许长期停留在新旧数据库名、连接串语义混杂的半状态

### 第五轮回滚点

- 若监控、告警、联调访问口径出现误报、漏报、面板失效或联调混乱，整轮回退到前三轮稳定状态
- 不允许在监控 / 告警失真状态下继续推进上线口径
- 若某项观测命名改动必须连带 Grafana 面板体系重构、外部告警平台重配或联调环境重建才能成立，该项立即回退并从第五轮剥离
