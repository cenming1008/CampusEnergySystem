# PLAN-20260408 Root Directory Governance And Entrypoint Convergence

> 状态：已阶段收口，暂不迁 archive，等待下一个主主题 | 负责人：规则 / 验收角色 | 更新时间：2026-04-08

## 背景

当前主区已从 `运行时命名契约迁移专题` 进入阶段收口状态，仓库需要切换到下一个主主题。

根目录当前同时承载了：

1. 长期稳定入口
2. 运行时配置
3. 开发与测试产物
4. 中间件数据目录
5. 快捷脚本与正式脚本入口
6. 历史残留与低价值噪音

虽然仓库已经有：

- `docs/guides/script-guidelines.md`
- `docs/README.md`
- `README.md` 中的根目录结构说明

但根目录仍存在以下治理问题：

- 根目录长期入口与运行时产物混杂，视觉噪音较重
- `bin/`、`scripts/`、根目录入口边界虽有规范，但活跃入口文档仍有失真
- 前一轮探索结论中存在事实偏差，不能直接沿用
- 根目录可见结构已经影响新主题导航、协作入口和仓库可读性

本主题不是一次性“大搬家”，而是围绕“根目录治理与入口收敛”做分角色、分阶段收敛。

## 目标

- 建立一个稳定、清晰、低噪音的仓库根目录入口叙事。
- 先收敛活跃入口文档，使主入口与真实文件存在状态一致。
- 明确根目录哪些只是运行产物 / 本地噪音，不纳入主入口叙事。
- 为后续是否进入噪音治理规则补齐或更深层结构判断提供稳定边界。

## 非目标

- 不做一次性全仓搬家
- 不做目录迁移
- 不顺手重构前后端代码结构
- 不顺手重写文档体系
- 不把运行时契约、容器命名、数据库命名再次并入本主题
- 不直接删除历史材料或运行数据目录
- 不在第一批处理 `five-role-orchestrator/` 的最终归类

## 实施步骤

### 第一批：入口文档收敛

第一批只做活跃入口文档修正：

- `README.md`
- `docs/README.md`
- `scripts/README.md`
- `bin/README.md`

第一批只处理：

- 活跃入口文档中的缺失文件引用
- 活跃入口文档中的旧项目名 / 旧绝对路径残留
- 根目录主入口叙事中过度暴露的运行产物 / 本地噪音
- `bin/` 与 `scripts/` 的入口边界表达收敛
- 对 `env.local.example` 仅允许处理活跃入口文档中的引用，不允许把文件本体纳入第一批实现范围

### 第二批：噪音治理规则补齐

第二批正式启用，但只补规则，不做真实清理：

## 风险与回滚

- 根目录整理最容易被误做成“大规模搬家”，导致入口失效、文档断链、脚本断链。
- 若第一批同时处理对象去留、噪音清理和目录移动，后续角色会失去共同边界。
- 若修改入口不同时校正文档与脚本引用，会出现仓库结构更整洁但使用路径更混乱的反效果。

回滚原则：

- 第一批若打断正式入口，应整批回退到第一批前状态。
- 规则轮只锁边界，不承担目录移动回滚。
