# Frontend Guidelines

## 目标
保持前端页面结构清晰、交互链路明确、组件职责单一、排查路径可复用，并默认服务于“园区综合能源管理系统 / 智慧园区 EMS”主线。

---

## 当前产品主线

前端线程默认按园区能源管理方向推进，当前阶段重点围绕以下页面展开：

1. 首页驾驶舱
2. 园区总览
3. 区域 / 楼栋能耗
4. 设备与表计管理
5. 实时监控
6. 告警中心
7. 能耗分析
8. 系统设置

页面组织、交互命名和状态建模，优先围绕以下核心业务对象展开：

- 园区
- 区域
- 楼栋
- 设备
- 表计
- 能源介质（电、水、气、冷、热）
- 分项能耗
- 告警
- 实时负荷

当前阶段不把煤矿专属对象作为前端主线页面重点，不新增以矿井、瓦斯抽采、通风、排水等为中心的页面叙事；若现有代码或页面中仍保留相关能力，默认按历史底座兼容看待，而不是继续扩张。

---

## 前端改动优先级

1. 先修功能失效
2. 再修状态异常
3. 再修结构混乱
4. 最后才考虑样式优化

---

## 排查顺序

当前端出现“按钮无效 / 页面无响应 / 弹窗不打开 / 列表不刷新”时，按以下顺序检查：

1. 按钮是否绑定 click 事件
2. 按钮是否被 disabled 条件锁住
3. click handler 是否真正执行
4. 本地状态是否更新
5. 组件间 props / emits 是否传递正常
6. 路由跳转是否被条件拦截
7. 接口请求是否真正发出
8. 接口成功后 UI 是否重新拉取或更新

---

## 组件修改原则

- 优先小改，不轻易拆大组件
- 一个组件只负责一类主要职责
- 页面容器组件负责组织数据和事件
- 展示组件尽量只负责渲染
- 避免把接口请求、复杂业务判断、UI 状态全塞进一个组件
- 页面结构优先围绕“园区 -> 区域 -> 楼栋 -> 设备 / 表计”展开，避免继续堆叠强行业化煤矿专属分组
- 图表、卡片和统计模块优先服务多能源接入、分层计量、分项分析、告警联动和驾驶舱展示

---

## 页面问题处理要求

每次前端问题处理后，应记录：
- 问题页面
- 涉及组件
- 根因位置
- 修改文件
- 验证方式
- 是否依赖后端

---

## 不建议的行为

- 未经分析直接重写整个页面
- 顺手改无关组件
- 一次性做大规模目录搬迁
- 前端线程直接修改后端逻辑
- 在没有明确产品计划的情况下，继续扩张煤矿专属页面、术语和交互路径

---

## 验证要求

至少完成以下之一：
- 本地点击验证
- 构建验证
- lint 验证

如果无法验证，要明确说明原因。
