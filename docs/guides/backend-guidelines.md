# Backend Guidelines

## 目标
保持后端接口边界清晰、返回结构稳定、权限逻辑明确、对前端影响可控。

---

## 后端改动优先级

1. 先修接口不可用
2. 再修权限异常
3. 再修返回结构不一致
4. 最后才做内部重构

---

## 接口排查顺序

当前端反馈“按钮点了没反应，但疑似后端问题”时，按以下顺序检查：

1. 路由是否存在
2. 接口方法是否匹配
3. 权限是否拦截
4. 请求参数是否正确解析
5. service 是否执行
6. 返回状态码是否合理
7. 返回结构是否与前端预期一致
8. 异常是否被吞掉或包装错误

---

## 修改原则

- 优先保持 API 兼容
- 优先最小修复
- 非必要不改动公共 schema
- 非必要不调整全局依赖注入和主流程
- 若必须改动接口契约，必须写入 handoff

---

## 每次修改后需要说明

- 修改接口
- 修改文件
- 影响范围
- 对前端的联调说明
- 验证结果
- 剩余风险

---

## 不建议的行为

- 后端线程直接去改前端页面
- 为修一个点而顺手大重构
- 无文档说明就改返回字段名
- 无兼容方案就调整接口结构
