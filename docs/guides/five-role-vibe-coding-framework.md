# CampusEnergySystem 五角色项目适配说明

> 本文不再承载通用 Five Role 方法论全文。通用分流方法已沉淀为个人 skill：`five-role-collaboration`。
>
> 在本仓库中，Five Role 的项目级适配、文档落点、产品语境、前后端边界与验收收口规则仍以本文、[AGENTS.md](../../AGENTS.md) 和 [AI 多角色协作 SOP](./ai-collaboration-sop.md) 为准。

---

## 1. 定位

Five Role 在本项目中是职责分流模型，不是必须同时启动五个 agent，也不是必须为每个小任务建立重流程。

- 通用职责分流：优先使用 `five-role-collaboration` skill 的判断框架。
- 项目规则落点：以 `AGENTS.md`、`docs/guides/*`、`docs/plans/*` 为准。
- 主题治理、daily 归档与收口：以 `docs/guides/ai-collaboration-sop.md` 为准。
- 产品语境：统一围绕“园区综合能源管理系统 / Campus Energy Management System / 智慧园区 EMS”推进。

项目内所有角色默认遵循：

1. 默认走能闭环的最短路径。
2. 先事实判断，再边界裁决，再进入实现。
3. 无接力、无边界变化、无主题变化，不动主区。
4. 前后端并行前，必须先有单一契约载体。
5. 每轮最小闭环结束后，必须执行一次阶段验收。
6. 连续有效打回达到阈值时，必须升级路径，不允许原地反复。

## 2. 项目五角色

| 角色 | 原兼容称呼 | 项目职责 | 是否常驻 |
| --- | --- | --- | --- |
| 预判 | 探索 | 做事实判断、根因定位、影响范围和最小路径建议 | 否 |
| 规则 | 规范 | 锁主题、术语、范围、契约、非目标和计划口径 | 否 |
| 前端 | 前端 | 处理页面、组件、状态、路由、交互和前端接口消费 | 是 |
| 后端 | 后端 | 处理接口、schema、service、权限、字段、状态码和返回结构 | 是 |
| 验收 | 验收 | 核对证据、判断通过 / 打回 / 收口、识别剩余风险 | 否 |

### 2.1 预判

进入条件：

- 根因不清楚。
- 不确定归前端、后端还是契约问题。
- 不确定是否属于当前主主题。
- 不确定是否需要前后端联动。

输出要求：

- 问题事实。
- 推荐路径。
- 本轮非目标。
- 下一角色。
- 必要时的最小契约草案或风险说明。

预判不负责长期规则制定，不把验证性修改扩成正式实现。

### 2.2 规则

进入条件：

- 主题、术语、对象边界或兼容口径不稳定。
- 需要决定是否建立或更新正式 `PLAN-*.md`。
- 需要裁决 breaking change、前后端并行边界或契约载体。

输出要求：

- 边界裁决结论。
- 稳定契约口径。
- 允许范围与禁止扩张项。
- 是否需要 `PLAN-*.md`。
- 验收口径。

规则不回做根因排查，不顺手做实现。

### 2.3 前端

进入条件：

- 问题已明确落在前端。
- 或接口契约已明确，可进行前端适配。

输出要求：

- 最小前端改动。
- 前端验证结果。
- 如需交接后端，写清接口路径、请求参数、返回依赖和当前 UI 影响。

前端不直接修改后端逻辑，不用 UI 兼容掩盖后端契约问题。

### 2.4 后端

进入条件：

- 问题已明确落在后端。
- 或契约已明确，需要提供或修正接口能力。

输出要求：

- 最小后端改动。
- 后端验证结果。
- 如需交接前端，写清接口变化、兼容边界和联调注意事项。

后端不直接修改前端页面逻辑，不无依据扩大 schema 或 service 重构。

### 2.5 验收

进入条件：

- 一轮最小闭环已完成。
- 当前主题拟阶段完成。
- 当前主题拟正式收口、归档或切换下一个主题。

输出要求：

- 对照当前 `PLAN-*.md`、`current-status.md`、`handoff.md` 的 checklist 结果。
- “通过 / 打回 / 收口”结论。
- 证据、未验证项、剩余风险和下一角色。

验收不引入新需求，不替代规则角色重写边界。

## 3. 30 秒分流卡

每轮开始先按以下顺序判断：

1. **能否单角色闭环？**  
   能：直接进入对应实现角色，完成后验收。

2. **根因或归属是否清楚？**  
   不清楚：先走预判。

3. **是否涉及主题、术语、契约、breaking change 或前后端并行？**  
   涉及：预判给事实后交规则裁决。

4. **是否跨多个模块、阶段或连续被打回？**  
   是：规则判断是否升级为正式 `PLAN-*.md`。

5. **是否已经完成？**  
   完成前必须走验收；主题结束时必须判断是否收口、归档、切换主主题。

## 4. 文档分级

### 4.1 轻量轮

适用：

- 单角色即可闭环。
- 不改变主题、契约或边界。
- 风险低，验证路径明确。

处理：

- 通常不动 `current-status.md` 和 `handoff.md`。
- 结束时在最终回复中写清目标、发现、修改、验证、风险和是否需要交接。

### 4.2 标准轮

适用：

- 需要角色接力。
- 需要稳定接口、字段、页面或验证口径。
- 当前主主题仍在推进。

处理：

- 维护 `docs/plans/current-status.md`。
- 维护 `docs/plans/handoff.md`。
- 必要时更新当前主题对应 `PLAN-*.md`。

### 4.3 重量轮

适用：

- 新主题。
- 跨前后端或跨多个模块。
- 涉及权限、部署、数据结构、协议、设备类型或正式验收门槛。
- 连续打回，需要重新锁边界。

处理：

- 必须建立或更新正式 `PLAN-*.md`。
- 必须明确目标、非目标、范围、契约、风险、验收标准和角色分工。
- 完成后按 SOP 执行 daily 快照与主题收口判断。

## 5. 本项目专属边界

### 5.1 产品语境

所有角色默认围绕以下主线推进：

- 多能源接入。
- 分层计量。
- 分项分析。
- 告警联动。
- 驾驶舱展示。

默认业务对象：

- 园区。
- 区域。
- 楼栋。
- 设备。
- 表计。
- 能源介质：电、水、气、冷、热。
- 分项能耗。
- 告警。
- 实时负荷。

旧有煤矿专属表述按历史或兼容层处理，不作为新功能默认方向继续扩张。

### 5.2 前后端契约

前后端并行前，必须先有单一契约载体。可选载体包括：

- 当前主题 `PLAN-*.md` 的接口契约段。
- `handoff.md` 中的临时联调契约。
- 后端 schema / API 响应结构变更说明。
- 测试用例中已经固定的请求与响应样例。

契约至少写清：

- 请求路径。
- 请求参数。
- 返回状态码。
- 返回结构。
- 空值和异常状态。
- 兼容边界。
- 前端展示或状态更新依赖。

### 5.3 设备与协议类任务

涉及新增设备类型、设备协议接入、设备字段分层、专属遥测 / 参数 / 控制链建模时，必须继续阅读：

- [device-data-classification.md](./device-data-classification.md)

涉及补偿类设备时，优先查看：

- [compensation-device-classification.md](./compensation-device-classification.md)

### 5.4 脚本类任务

涉及脚本新增、迁移、整理或入口调整时，必须继续阅读：

- [script-guidelines.md](./script-guidelines.md)

脚本治理不得借机扩到仓库结构重构，也不得顺手处理无关历史脚本。

## 6. 与其他 skill 的关系

`five-role-collaboration` 是分流层，不替代项目规则。

在本仓库中优先级为：

1. 用户本轮明确要求。
2. `AGENTS.md` 与本仓库 `docs/guides/*`。
3. `five-role-collaboration` skill。
4. 其他执行型 skill 或通用方法。

推荐组合：

- 根因不明：Five Role 判断进入预判，再使用系统化调试方法。
- 行为改动：Five Role 判断实现角色，再按风险决定是否 TDD。
- 多步骤主题：Five Role 判断重量轮，再建立或更新 `PLAN-*.md`。
- 完成前：Five Role 进入验收，再做验证证据核对。
- 并行执行：Five Role 先锁契约，再考虑是否使用 sub-agent。

如果其他 skill 会把轻量轮过度流程化，以本项目轻量 / 标准 / 重量分级为准，只吸收其中必要技术方法。

## 7. 交接格式

角色交接时使用以下最小格式：

```text
角色：
本次目标：
发现的问题：
修改文件：
验证结果：
剩余风险：
需要交接给谁：
```

前端交后端必须补充：

- 接口路径。
- 请求参数。
- 返回状态码 / 返回结构。
- 前端依赖什么结果。

后端交前端必须补充：

- 改了哪个接口。
- 是否影响旧逻辑。
- 前端需要如何联调。

验收交接必须补充：

- 通过 / 打回 / 收口结论。
- 证据。
- 未验证项。
- 下一主主题建议，如有。
