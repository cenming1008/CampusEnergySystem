# 规范指南

> 面向长期维护的稳定规则层，约定“什么内容写到哪里、怎么写、谁来维护”。

---

## 适用范围

本目录用于存放跨阶段、跨需求、可长期复用的规范文档，包括但不限于：

- 文档体系与信息架构
- 计划编写与变更管理
- 协作流程与交付约束
- 命名、评审、验收等通用规则

不适合放在这里的内容：

- 一次性方案或阶段性推进记录 → 放到 `docs/plans/`
- 已完成功能的历史总结 → 放到 `docs/06-历史记录/`
- 具体功能用法、部署步骤、故障排查 → 继续放在现有分类目录

## 使用顺序

1. 先读 [文档体系规范.md](./文档体系规范.md)，判断文档应该落在哪个目录
2. 再读 [变更计划规范.md](./变更计划规范.md)，判断当前改动是否需要先写计划
3. 若涉及多人或智能体协作，再读 [AI 多线程协作 SOP](./ai-collaboration-sop.md)
4. 若涉及 Codex 五线程接力、高频开发、任务分流或线程切换，再读 [five-thread-vibe-coding-framework.md](./five-thread-vibe-coding-framework.md)
5. 若涉及多人或智能体协作，同时阅读根目录 `AGENTS.md`

---

## 维护原则

1. 本目录只保留稳定规则，不记录一次性执行细节
2. 新增规范前，优先更新已有规范，避免并列冲突
3. 规范变更时，应同步检查 `docs/README.md` 与 `AGENTS.md`
