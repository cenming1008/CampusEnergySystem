## 🔄 自动清理机制

### 系统已配置自动清理

**配置位置**: `app/core/logger.py`

```python
logger.add(
    "logs/ems_app_{time:YYYY-MM-DD}.log",
    rotation="00:00",                              # 每天00:00轮转
    retention=f"{settings.log_retention_days} days",  # 保留7天
    level=settings.log_level,
)

logger.add(
    "logs/ems_error_{time:YYYY-MM-DD}.log",
    rotation="00:00",
    retention="30 days",                           # 错误日志保留30天
    level="ERROR",
)
```

**自动清理策略**：
- ✅ **应用日志**: 自动删除超过 7 天的日志
- ✅ **错误日志**: 自动删除超过 30 天的日志
- ✅ **每天凌晨**: 自动执行清理和轮转

**修改保留天数**：

编辑 `.env` 文件：
```bash
LOG_RETENTION_DAYS=14  # 改为保留14天
```

或修改 `app/core/settings.py` 中的默认值：
```python
log_retention_days: int = Field(
    default=7,  # 修改这里
    env="LOG_RETENTION_DAYS"
)
```

## 📊 查看日志占用空间

### 快速查看

```bash
# 查看日志目录总大小
du -sh logs/

# 查看每个日志文件大小
ls -lh logs/

# 按大小排序显示
ls -lhS logs/

# 统计文件数量
ls logs/*.log | wc -l
```

### 详细分析

```bash
# 查看最近7天的日志大小
find logs -name "*.log" -type f -mtime -7 -exec du -h {} \; | sort -h

# 查看占用空间最大的5个日志文件
du -h logs/*.log | sort -rh | head -5

# 统计总占用空间
du -sh logs/ && du -h logs/*.log | awk '{sum+=$1} END {print "Total:", sum}'
```

## ⚙️ 日志配置说明

### 环境变量配置

编辑 `.env` 文件：

```bash
# ==================== 日志配置 ====================
LOG_LEVEL=INFO               # 日志级别：DEBUG, INFO, WARNING, ERROR, CRITICAL
LOG_DIR=logs                 # 日志目录
LOG_RETENTION_DAYS=7         # 应用日志保留天数
```

### 日志级别说明

| 级别 | 说明 | 适用场景 |
|------|------|---------|
| **DEBUG** | 详细调试信息 | 开发环境，排查问题 |
| **INFO** | 一般信息 | 生产环境（默认） |
| **WARNING** | 警告信息 | 生产环境，减少日志量 |
| **ERROR** | 错误信息 | 仅记录错误 |
| **CRITICAL** | 严重错误 | 仅记录致命错误 |

## 🎯 最佳实践

### 1. 生产环境建议

```bash
# 生产环境配置
LOG_LEVEL=INFO               # 使用INFO级别
LOG_RETENTION_DAYS=30        # 保留30天日志
```

**理由**：
- INFO级别足够诊断问题
- 保留30天便于追溯历史问题
- 避免DEBUG级别产生过多日志

### 2. 开发环境建议

```bash
# 开发环境配置
LOG_LEVEL=DEBUG              # 使用DEBUG级别
LOG_RETENTION_DAYS=3         # 只保留3天
```

**理由**：
- DEBUG级别便于调试
- 开发环境不需要长期保留
- 减少磁盘占用

### 3. 定期清理计划

**方案A: 手动定期清理**
```bash
# 每周执行一次
./scripts/shell/cleanup_logs.sh 7
```

**方案B: 使用cron自动清理**（可选）
```bash
# 编辑crontab
crontab -e

# 添加定时任务（每周日凌晨3点清理）
0 3 * * 0 /path/to/MineEnergySystem/scripts/shell/cleanup_logs.sh 7 <<< 'y'
```

**方案C: 依赖自动清理**（推荐）
- 使用系统配置的自动清理机制
- 无需手动干预
- 系统会自动处理

## 🚨 常见问题

### Q1: 日志目录占用空间过大

**原因**：
- 日志级别设置为DEBUG
- 保留天数过长
- 高频率操作产生大量日志

**解决方案**：
```bash
# 1. 调整日志级别
echo "LOG_LEVEL=INFO" >> .env

# 2. 减少保留天数
echo "LOG_RETENTION_DAYS=7" >> .env

# 3. 立即清理旧日志
./scripts/shell/cleanup_logs.sh 7

# 4. 重启服务
docker compose restart backend
```

---

### Q2: 日志文件没有自动清理

**检查清单**：

1. **检查配置**
   ```bash
   # 查看当前配置
   grep LOG_RETENTION .env
   ```

2. **检查日志配置**
   ```bash
   # 查看logger配置
   cat app/core/logger.py | grep retention
   ```

3. **检查服务运行**
   ```bash
   # 确认服务正在运行
   docker compose ps
   ```

**解决方案**：
- 确保服务持续运行（自动清理在服务运行时执行）
- 检查配置是否正确加载
- 重启服务以应用新配置

---

### Q3: 如何备份重要日志

```bash
# 创建备份目录
mkdir -p logs_backup

# 备份所有日志
cp -r logs/* logs_backup/

# 备份特定日期的日志
cp logs/ems_app_2026-01-24.log logs_backup/

# 压缩备份
tar -czf logs_backup_$(date +%Y%m%d).tar.gz logs/

# 备份到其他位置
rsync -av logs/ /path/to/backup/logs/
```

---

### Q4: Docker容器重启后日志消失

**原因**：日志目录没有挂载到宿主机

**检查 docker-compose.yml**：
```yaml
services:
  backend:
    volumes:
      - ./logs:/app/logs  # 确保有这一行
```

**解决方案**：
1. 确认 docker-compose.yml 中有日志目录挂载
2. 重启容器
3. 验证日志目录

```bash
# 检查挂载
docker inspect campus_backend | grep logs

# 重启容器
docker compose restart backend
```

## 📝 清理脚本使用示例

### 示例1: 每周清理

```bash
#!/bin/bash
# weekly_cleanup.sh - 每周清理脚本

echo "开始每周日志清理..."

# 清理应用日志（7天前）
./scripts/shell/cleanup_logs.sh 7 <<< 'y'

# 查看清理后状态
echo "清理完成，当前状态："
du -sh logs/
ls -l logs/ | wc -l
```

### 示例2: 清理前备份

```bash
#!/bin/bash
# cleanup_with_backup.sh - 清理前先备份

BACKUP_DIR="logs_backup_$(date +%Y%m%d)"

# 创建备份
echo "正在备份日志..."
mkdir -p "$BACKUP_DIR"
cp -r logs/* "$BACKUP_DIR/"
tar -czf "${BACKUP_DIR}.tar.gz" "$BACKUP_DIR"
rm -rf "$BACKUP_DIR"

echo "备份完成: ${BACKUP_DIR}.tar.gz"

# 执行清理
./scripts/shell/cleanup_logs.sh 7 <<< 'y'
```
