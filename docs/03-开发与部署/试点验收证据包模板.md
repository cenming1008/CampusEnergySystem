# 试点验收证据包模板

> 用于把“能跑”沉淀成“能交付、能复盘、能审批”的证据包。

---

## 1. 建议目录结构

建议每次试点演练或部署都生成独立目录，例如：

```text
artifacts/pilot/20260326_193000/
├── summary.md
├── logs/
├── load/
├── backup_restore/
└── notifications/
```

其中：

- `summary.md`：本次演练结论
- `logs/`：发布前检查、测试、迁移、Compose 校验日志
- `load/`：压测原始 JSON 与基线判定结果
- `backup_restore/`：备份、校验、恢复演练记录
- `notifications/`：告警通道验收截图或文本记录

---

## 2. 最低必备证据

### 环境复现

- `release_readiness.sh` 执行日志
- `check_production_readiness.py --env-file .env.prod` 输出
- 后端单元测试执行结果
- `alembic upgrade head --sql` 或真实迁移日志

### 部署与运行

- `deploy_prod.sh` 结果
- `pilot_smoke_test.sh` 结果
- `/health` `/health/live` `/health/ready` `/metrics` 验收截图或日志

### 备份与恢复

- `backup.sh --label ...` 结果
- `restore.sh --verify-only ...` 结果
- `restore_drill.sh` 演练记录
- 如发生回滚，补充 `rollback_prod.sh` 结果

### 通知通道

- `send_test_alert.py` 输出
- Webhook 或邮件送达记录
- 值守接收人确认时间

### 设备接入

- 试点站点名称、设备数量、设备类型
- MQTT Topic 与 Payload 冻结版编号
- 去重、补传、时间戳规则确认记录

### 容量基线

- `stress_test.py` 原始 JSON 报告
- `evaluate_capacity_baseline.py` 判定结果
- 本次阈值说明，例如最小吞吐、最大 p95、最小成功率

## 3. 推荐结论模板

```md
# 试点验收结论

- 站点: xx 矿区 / xx 车间
- 时间: 2026-03-26 19:30 CST
- 版本: <git sha / release tag>
- 结论: 通过 / 限制通过 / 不通过

## 通过项

- 发布前检查通过
- 备份校验通过
- 冒烟通过
- 告警送达通过

## 风险项

- 真实设备接入仍需观察 72 小时
- 容量基线仅覆盖单实例

## 下一步

- 安排 7-14 天试运行
- 完成现场值守交接
```

## 4. 推荐命令

```bash
bash ./scripts/shell/pilot_readiness.sh --env-file .env.prod
python scripts/python/stress_test.py --endpoint /health/live --workers 20 --duration-seconds 60 --output artifacts/pilot/load/health_live.json
python scripts/python/evaluate_capacity_baseline.py --report artifacts/pilot/load/health_live.json --min-rps 20 --max-p95-ms 200 --min-success-rate 99 --expect-status-code 200 --output-md artifacts/pilot/load/health_live.md
```
