# MineEnergySystem 正式投产前差距清单

> 基于 2026-03-26 试点验收结果整理  
> 目标：从“单站试点可交付”推进到“正式工业投产可交付”

---

## 1. 当前定位

当前项目已经达到：

- 单站试点可交付
- 单实例可运行
- 具备基础监控、告警、备份恢复、MQTT 接入与认证能力

当前尚未达到：

- 正式工业投产的完整交付标准

因此后续工作重点不再是“补基础功能”，而是“补正式投产治理能力”。

---

## 2. P0 差距

这些项建议在正式投产前必须完成。

### 2.1 正式告警通道切换

当前状态：

- 已验证 webhook 发送链路
- 但仍使用临时本地接收器完成测试

正式投产前要求：

- 接入正式企业微信 / 飞书 / 邮件网关
- 完成一次真实送达验收
- 明确值守接收人和升级路径

### 2.2 远端部署实跑

当前状态：

- 远端部署工作流已实现
- 但尚未在真实 GitHub Environment 中实跑

正式投产前要求：

- 配置真实 `DEPLOY_HOST`、`DEPLOY_USER`、`DEPLOY_SSH_PRIVATE_KEY`、`ENV_PROD_FILE`
- 在 staging 或 production 环境完成一次真实发布
- 保留部署日志与结果物

### 2.3 现场真实设备联调

当前状态：

- MQTT 测试消息接入已通过
- 自动建档、台账、入库均已验证

正式投产前要求：

- 至少完成一轮真实设备接入
- 冻结 topic / payload / timestamp / 补传规则
- 形成接入验收记录

### 2.4 真实恢复演练

当前状态：

- 脚本和流程已具备
- 但本次主要验证集中在 readiness、baseline、smoke、告警、MQTT

正式投产前要求：

- 完整执行备份、恢复、回滚演练
- 形成演练记录
- 明确恢复时间目标和责任人

---

## 3. P1 差距

这些项不阻止试点，但建议在正式投产前补齐。

### 3.1 高可用能力

当前状态：

- 当前更偏单实例

建议补齐：

- 后端多实例
- 反向代理与健康摘流
- 数据库/缓存高可用策略

### 3.2 监控指标增强

当前状态：

- `/metrics` 可用
- 当前未见 `process_*` 指标

建议补齐：

- 明确是否需要标准进程指标
- 明确核心业务指标、错误率、延迟、MQTT 死信、调度失败率

### 3.3 长时间稳定性观察

当前状态：

- 已完成功能级验收
- 尚未进行 7 到 14 天连续试运行观察

建议补齐：

- 连续观测错误率、重启、死信、告警噪音、数据库连接池表现

---

## 4. P2 差距

这些项更偏长期工程化提升。

### 4.1 运维制度化

- 值守手册
- 故障分级响应
- 发布窗口制度
- 升级审批流程

### 4.2 更完整安全治理

- 密钥轮换制度
- 环境配置托管
- 更细粒度审计与权限模型

### 4.3 更完整性能治理

- 容量规划
- 长周期压测
- 站点扩容预案

---

## 5. 建议路线图

### 第一阶段：试点收口

- 正式告警通道上线
- 远端部署实跑
- 真实设备联调
- 真实恢复演练

### 第二阶段：试运行观察

- 7 到 14 天稳定运行
- 持续收集告警、性能、MQTT 接入数据
- 修复现场暴露问题

### 第三阶段：正式投产准备

- 高可用
- 值守制度
- 更完整监控
- 正式投产审批材料
