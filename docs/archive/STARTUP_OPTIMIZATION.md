# 启动速度优化指南

## 🐌 为什么启动慢？

### 主要原因

1. **首次启动需要下载镜像**（最耗时）
   - TimescaleDB 镜像：~500MB
   - Python 基础镜像：~150MB
   - 其他服务镜像：~100MB
   - **总计约 750MB，需要下载时间**

2. **构建后端镜像**（首次启动）
   - 安装系统依赖（apt-get）
   - 安装 Python 包（pip install）
   - 编译 C 扩展（bcrypt 等）
   - **首次构建可能需要 3-5 分钟**

3. **健康检查等待**
   - 数据库需要等待健康检查通过
   - 后端等待所有依赖服务就绪
   - **健康检查间隔增加了等待时间**

4. **数据库初始化**
   - 首次启动需要初始化数据库
   - 创建表结构
   - 启用 TimescaleDB 扩展

5. **Mac Docker Desktop 性能**
   - Docker Desktop 在 Mac 上使用虚拟机
   - 性能比原生 Linux 慢一些

---

## ⚡ 优化方案

### 方案一：优化健康检查（推荐）

减少健康检查的等待时间：

```yaml
healthcheck:
  interval: 5s      # 从 10s 改为 5s
  timeout: 3s        # 从 5s 改为 3s
  retries: 3         # 从 5 改为 3
```

### 方案二：并行启动（已优化）

当前配置已经使用了 `depends_on` 和健康检查，确保服务按顺序启动。

### 方案三：使用 Docker 镜像缓存

首次构建后，后续启动会使用缓存，速度会快很多。

### 方案四：减少后端启动等待时间

优化后端的 `start_period`：

```yaml
healthcheck:
  start_period: 20s  # 从 40s 改为 20s
```

## 📊 启动时间对比

| 阶段 | 首次启动 | 后续启动 |
|------|----------|----------|
| 下载镜像 | 2-5 分钟 | 0（已缓存） |
| 构建镜像 | 3-5 分钟 | 10-30 秒（使用缓存） |
| 服务启动 | 30-60 秒 | 20-40 秒 |
| **总计** | **5-10 分钟** | **30-70 秒** |

## 🚀 快速启动技巧

### 1. 预下载镜像（可选）

```bash
# 提前下载所有镜像
docker compose pull
```

### 2. 使用构建缓存

```bash
# 不要使用 --no-cache
docker compose build  # 使用缓存
```

### 3. 跳过健康检查（开发环境）

如果只是开发测试，可以临时移除健康检查，加快启动：

```yaml
# 注释掉 depends_on 的 condition
depends_on:
  - db
  - redis
  - mqtt
  # condition: service_healthy  # 临时注释
```

## 💡 实际优化建议

### 对于开发环境

1. **减少健康检查间隔**（已优化）
2. **使用 Docker 缓存**（自动）
3. **保持容器运行**（不要频繁重启）

### 对于生产环境

1. **保持健康检查**（确保服务稳定）
2. **使用预构建镜像**（避免构建时间）
3. **优化资源分配**（Docker Desktop 设置）
