# 数据清理功能故障排查

## 🔍 问题描述

前端调用数据清理API时出现 **404 错误**：`Request failed with status code 404`

## ✅ 已修复的问题

### 1. 前端API调用方式修复

**问题**：POST请求的查询参数传递方式不正确

**修复前**：
```typescript
return request.post('/data-cleanup/cleanup', null, {
  params: { hours }
})
```

**修复后**：
```typescript
return request.post(`/data-cleanup/cleanup?hours=${hours}`)
```

### 2. 添加测试端点

添加了 `/data-cleanup/test` GET端点，用于验证路由是否正常工作。

## 🔧 排查步骤

### 步骤1：检查后端服务是否重启

**重要**：添加新的API端点后，必须重启后端服务！

```bash
# Docker环境
docker compose restart backend

# 或本地开发环境
# 停止当前服务（Ctrl+C），然后重新启动
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8088
```

### 步骤2：验证路由是否注册

访问测试端点：
```bash
# 测试端点（无需认证）
curl http://localhost:8088/data-cleanup/test

# 应该返回：
# {"status": "ok", "message": "数据清理API端点正常工作"}
```

### 步骤3：检查API文档

访问 FastAPI 自动生成的文档：
```
http://localhost:8088/docs
```

在文档中搜索 `data-cleanup`，应该能看到：
- `POST /data-cleanup/cleanup` - 清理数据
- `GET /data-cleanup/stats` - 获取统计
- `GET /data-cleanup/test` - 测试端点

### 步骤4：检查认证

数据清理API需要认证，确保：
1. 已登录系统
2. Token有效
3. 请求头包含 `Authorization: Bearer <token>`

### 步骤5：检查后端日志

查看后端日志，确认是否有错误：

```bash
# Docker环境
docker compose logs backend | tail -50

# 本地环境
tail -f logs/ems_app_$(date +%Y-%m-%d).log
```

查找以下内容：
- `数据清理API端点正常工作` - 说明路由已注册
- `404` 或 `Not Found` - 说明路由未找到
- `401` 或 `Unauthorized` - 说明认证失败

## 🐛 常见问题

### 问题1：404 Not Found

**原因**：
- 后端服务未重启
- 路由未正确注册
- URL路径错误

**解决方案**：
1. 重启后端服务
2. 检查 `app/main.py` 中的路由注册
3. 检查前端请求的URL路径

### 问题2：401 Unauthorized

**原因**：
- 未登录
- Token过期
- Token格式错误

**解决方案**：
1. 重新登录
2. 检查浏览器控制台的请求头
3. 检查Token是否有效

### 问题3：500 Internal Server Error

**原因**：
- 数据库连接失败
- SQL执行错误
- 服务内部错误

**解决方案**：
1. 查看后端日志
2. 检查数据库连接
3. 检查SQL语句是否正确

## 📝 验证清单

- [ ] 后端服务已重启
- [ ] 路由已正确注册（检查 `app/main.py`）
- [ ] 前端API调用路径正确（`/data-cleanup/cleanup?hours=1`）
- [ ] 用户已登录且Token有效
- [ ] 后端日志无错误信息
- [ ] API文档中可以找到端点

## 🚀 快速修复命令

```bash
# 1. 重启后端服务（Docker）
docker compose restart backend

# 2. 查看日志
docker compose logs -f backend

# 3. 测试端点
curl http://localhost:8088/data-cleanup/test
```

## 📞 如果问题仍然存在

1. **检查浏览器控制台**：
   - 打开开发者工具（F12）
   - 查看 Network 标签
   - 找到失败的请求
   - 查看请求URL、请求头、响应内容

2. **检查后端日志**：
   - 查看详细的错误信息
   - 确认路由是否被调用

3. **手动测试API**：
   ```bash
   # 获取Token后
   curl -X POST "http://localhost:8088/data-cleanup/cleanup?hours=1" \
     -H "Authorization: Bearer YOUR_TOKEN"
   ```
