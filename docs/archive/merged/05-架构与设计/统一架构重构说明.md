# 统一架构重构说明

**重构日期**: 2026-01-24  
**版本**: v2.2.0 → 统一架构  
**重构目标**: 将多能源功能真正融入系统核心

---

## 🎯 重构背景

### 旧架构的问题

v2.1.0 虽然实现了多能源功能，但存在明显的架构问题：

```
❌ 问题 1: 双轨制数据存储
   - DeviceData (旧表，仅电力)
   - EnergyData (新表，多能源)
   - 数据分散，难以统一管理

❌ 问题 2: 服务层分离
   - DeviceService: 只管设备 CRUD
   - EnergyService: 只管能源数据
   - 两者缺乏整合

❌ 问题 3: API 分散
   - /devices - 设备管理
   - /telemetry - 电力数据
   - /energy - 多能源数据
   - 用户需要记住多个端点

❌ 问题 4: 设备创建复杂
   - 需要手动设置多个字段
   - device_type, device_category, energy_type, unit...
   - 容易出错，不友好

❌ 问题 5: 扩展困难
   - 添加新设备类型需要修改多处代码
   - 缺乏统一的配置机制
```

### 用户反馈

> "多能源功能像是贴膏药，没有真正融入系统"
> 
> "我需要的是完整的一套系统，而不是独立的模块"
> 
> "添加新设备太复杂，希望能自动配置"

## 🔧 关键改进

### 1. 设备类型注册表

**新增**: `app/core/device_registry.py`

集中管理所有设备类型的元数据：

```python
@dataclass
class DeviceTypeConfig:
    device_type: str          # 设备类型标识
    category: DeviceCategory  # 设备类别
    energy_type: EnergyType   # 能源类型
    name_zh: str             # 中文名称
    unit: str                # 单位
    default_capacity: float  # 默认容量
    required_fields: List    # 必需字段
    optional_fields: List    # 可选字段
```

**优势**:
- ✅ 配置化管理
- ✅ 类型安全
- ✅ 易于扩展

### 2. 智能设备创建

**新增**: `DeviceService.create_device_smart()`

```python
# 旧方式 - 需要手动填写所有字段
device = Device(
    name="1号水表",
    sn="WATER001",
    device_type="water_meter",
    device_category="water_meter",  # 手动
    energy_type="water",            # 手动
    unit="m³/h",                    # 手动
    rated_capacity=50.0             # 手动
)

# 新方式 - 自动配置
device = DeviceService.create_device_smart(
    session, 
    name="1号水表",
    sn="WATER001",
    device_type="water_meter"  # 只需指定类型！
)
# 系统自动设置其他字段
```

### 3. 统一数据上报

**新增**: `DeviceService.report_device_data()`

```python
# 统一接口，适配所有设备类型
DeviceService.report_device_data(
    session,
    device_id=1,
    data={
        "consumption": 10.5,
        "flow_rate": 2.3,
        "pressure": 0.3,
        # ... 其他字段
    }
)
```

**自动处理**:
- ✅ 字段验证（根据设备类型）
- ✅ 数据路由（保存到正确的表）
- ✅ 碳排放计算
- ✅ 日志记录

### 4. API 统一

**新端点设计**:

```bash
# 设备管理
GET    /devices/                # 列表（支持筛选）
GET    /devices/types           # 支持的设备类型
GET    /devices/types/{type}    # 设备类型详情
POST   /devices/                # 智能创建
GET    /devices/{id}            # 设备详情
PUT    /devices/{id}            # 更新设备
DELETE /devices/{id}            # 删除设备

# 数据管理（整合到设备端点下）
POST   /devices/{id}/data       # 数据上报
GET    /devices/{id}/data       # 查询数据
GET    /devices/{id}/statistics # 统计分析
```

**优势**:
- ✅ RESTful 设计
- ✅ 资源层次清晰
- ✅ 易于理解和使用

## 🎓 最佳实践

### 1. 设备类型优先

创建设备时，首先确定正确的 `device_type`：

```bash
# 查看所有支持的类型
GET /devices/types

# 查看特定类型的详情
GET /devices/types/water_meter
```

### 2. 使用智能创建

优先使用智能创建接口：

```python
# ✅ 推荐
device = DeviceService.create_device_smart(
    session,
    name="设备名称",
    sn="序列号",
    device_type="设备类型"
)

# ❌ 不推荐（除非有特殊需求）
device = Device(...)
DeviceService.create_device(session, device)
```

### 3. 统一数据上报

所有设备使用同一个接口：

```python
# 适用于所有设备类型
DeviceService.report_device_data(
    session,
    device_id=device.id,
    data=data_dict
)
```

### 4. 扩展新设备类型

添加新设备类型只需配置：

```python
# app/core/device_registry.py
self.register(DeviceTypeConfig(
    device_type="new_device",
    category=DeviceCategory.LOAD,
    energy_type=EnergyType.ELECTRICITY,
    name_zh="新设备",
    unit="kW",
    ...
))
```

重启服务即可使用。
