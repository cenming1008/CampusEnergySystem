# PLAN-20260327-文档体系建设

> 状态：已完成 | 负责人：Codex | 更新时间：2026-03-27

---

## 背景

项目现有文档已经覆盖启动、功能、部署、排障和架构，但缺少一层长期稳定的“规范文档体系”入口，导致以下问题：

- 文档规范、协作规则和计划方式分散在多个 README 或历史文档中
- 新增文档时不容易判断该更新旧文档还是新建目录
- 智能体或协作者接手时，缺少统一的范围边界和最小执行约束

## 目标

- 建立 `docs/guides/` 作为长期稳定规范入口
- 建立 `docs/plans/` 作为实施计划与模板入口
- 在根目录新增 `AGENTS.md`，统一协作边界与执行规则
- 更新 `docs/README.md`，让新体系可被导航发现

## 非目标

- 不修改业务代码
- 不重写现有主题文档内容
- 不清理历史文档或重做旧目录命名

## 范围

涉及目录或文件：

- `docs/guides/`
- `docs/plans/`
- `docs/README.md`
- `AGENTS.md`

明确不改动：

- `app/`
- `frontend/src/`
- 所有现有业务实现文件

## 实施步骤

1. 梳理现有 `docs/`、根目录 README、前后端 README 中已有规范
2. 提炼长期可复用的规则，写入 `docs/guides/`
3. 建立计划模板与当前计划，写入 `docs/plans/`
4. 编写根目录 `AGENTS.md`，约束协作方式与最小验证规则
5. 更新 `docs/README.md`，补充新目录导航

## 风险与回滚

- 风险：新规范与现有 README 中的旧表述不一致
  - 应对：以“新增统一入口、尽量不推翻原术语”为原则，并在导航中明确角色
- 风险：计划目录被误当成历史归档目录
  - 应对：在 `docs/guides/` 和 `docs/plans/README.md` 中显式写清边界

## 验收标准

- [x] `docs/guides/` 已建立并包含目录 README 与至少 2 篇规范文档
- [x] `docs/plans/` 已建立并包含目录 README、模板文件和当前计划文档
- [x] 根目录存在 `AGENTS.md`，并包含文档落点、协作边界和执行规则
- [x] `docs/README.md` 已补充新目录导航
- [x] 本次改动未触碰业务代码文件
