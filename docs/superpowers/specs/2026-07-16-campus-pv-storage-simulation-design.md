# 园区光储协同仿真与 EMS 控制系统设计

## 1. 文档状态

- 日期：2026-07-16
- 状态：用户已逐节确认
- 当前阶段：设计完成，等待用户复核后编写实施计划
- 适用产品：园区综合能源管理系统
- 主题等级：重量轮新主题

本设计定义一个面向校招展示、可在现有园区 EMS 中运行的光储协同仿真系统。第一阶段不依赖真实储能硬件，通过系统级电池、BMS 和 PCS 仿真完成遥测、控制、回执、告警与策略闭环；后续允许用真实 BMS/PCS 通信适配器替换仿真设备，而不推翻平台、控制和页面契约。

## 2. 背景与现状

仓库已经存在储能基础能力：

- `StorageTelemetry` 时序模型；
- MQTT 储能扩展字段提取和入库；
- SOC、SOH、有功/无功、直流侧、三相交流侧、频率、温度、运行状态和电量统计字段；
- 储能专属查询接口和监控聚合服务；
- 储能监控页面；
- SOC、SOH、温度和功率平台告警规则；
- 储能入库、接口和页面基础测试。

现有实现主要是遥测监控骨架，尚未形成以下闭环：

- 储能资产参数与设备能力模型；
- BMS、PCS 和电池系统级仿真；
- 储能控制命令、回执与超时处理；
- 光伏、负荷和分时电价场景；
- 削峰填谷与光伏消纳实时规则；
- 日前优化调度；
- 计划与实际执行偏差分析；
- 无储能、规则控制和优化调度的量化对比。

## 3. 目标

第一阶段交付一个可重复演示的园区光储协同系统，具体目标为：

1. 仿真 500 kWh/250 kW 储能系统、200 kWp 光伏和峰值约 400 kW 的园区负荷。
2. 通过 MQTT 完成仿真 BMS/PCS 遥测上报、功率命令下发和控制回执。
3. 实现 SOC、温度、故障、通信、并网状态等安全联锁。
4. 以规则控制实现光伏富余吸收、需量削峰和峰谷电价响应。
5. 以 15 分钟为时段生成 24 小时、96 点日前优化计划。
6. 展示能量流、计划与实际功率、SOC、告警、命令状态和收益对比。
7. 提供固定演示场景、自动化测试、一键启动和结果报告。
8. 保留未来真实 BMS/PCS 接入所需的稳定设备、遥测和控制边界。

## 4. 非目标

第一阶段不实现：

- 电芯电化学反应、精确内阻和端电压曲线；
- 电池热场和热失控传播仿真；
- PCS 开关器件、PWM 或底层电流环控制；
- 并网暂态、频率支撑、虚拟同步机或孤岛切换；
- 配电网潮流、状态估计、继电保护和短路分析；
- 真实厂商私有 BMS/PCS 协议；
- 电池簇、模组和单体级海量遥测；
- 机器学习负荷或光伏预测；
- 对真实储能设备安全标准或保护定值作通用承诺。

项目对外名称采用“园区储能系统级仿真与 EMS 控制平台”或“园区光储协同 EMS”，不称为电池电化学数字孪生、PCS 底层控制系统或完整电力系统仿真平台。

## 5. 总体架构

系统分为五层：

1. 场景仿真层：生成园区负荷、光伏出力、电价和异常事件。
2. 储能设备仿真层：模拟电池、BMS、PCS、功率跟随和控制回执。
3. 实时 EMS 层：执行规则控制、安全联锁和计划跟踪。
4. 园区 EMS 平台层：负责 MQTT、入库、告警、API、WebSocket 和控制日志。
5. 日前优化层：生成 96 点充放电计划，由实时 EMS 安全执行。

数据和控制方向如下：

```text
场景仿真器（负荷、光伏、电价）
              ↓
实时 EMS ← 日前优化计划
   ↓ 目标功率
储能设备仿真器（Battery + BMS + PCS）
   ↓ 遥测与回执
MQTT 接入层
   ↓
园区 EMS（存储、告警、API、WebSocket）
   ↓
光储总览、储能工作台、调度与收益页面
```

未来真实设备接入时，仅替换储能设备仿真器及其协议适配器。实时 EMS、平台接口、控制日志、调度模型和页面继续复用。

## 6. 场景与默认规模

默认参数：

| 参数 | 默认值 |
| --- | --- |
| 储能额定容量 | 500 kWh |
| PCS 额定功率 | 250 kW |
| 光伏装机容量 | 200 kWp |
| 园区峰值负荷 | 约 400 kW |
| SOC 安全范围 | 10%～90% |
| SOC 优化软范围 | 15%～85% |
| 充电效率 | 95% |
| 放电效率 | 95% |
| 调度间隔 | 15 分钟 |
| 实时规则周期 | 60 秒 |
| MQTT 遥测周期 | 5 秒 |
| 仿真内部步长 | 1 秒 |
| 需量目标 | 300 kW，可配置 |

固定场景包括：

- 晴天工作日；
- 阴天工作日；
- 周末低负荷；
- 午间光伏富余；
- 晚高峰负荷突增；
- 光伏骤降；
- SOC 过低；
- 电池过温；
- PCS 故障；
- MQTT 通信中断。

仿真支持实时、10 倍、60 倍和“一天压缩为约 5 分钟”的演示速度。仿真消息必须标记 `data_source=simulated`，页面不得将其伪装为真实设备数据。

## 7. 设备分类与数据分层

### 7.1 设备身份

第一版将整套储能柜建模为一个逻辑设备：

```text
device_category = storage
device_subtype = battery_energy_storage_system
device_code = STO-001
energy_type = electricity
```

电池、BMS 和 PCS 是该逻辑设备内部的明确组件边界，第一阶段不把电池单体分别注册为平台设备。

### 7.2 资产档案

新增储能资产档案，至少包含：

- 额定容量和 PCS 额定功率；
- SOC 安全上下限和优化软上下限；
- 最大充电、放电功率；
- 充电、放电效率；
- 额定交流、直流电压；
- 电池类型；
- BMS、PCS 型号和协议版本；
- 安装位置、投运日期和数据来源。

### 7.3 实时遥测

继续使用 `StorageTelemetry` 承载既有字段：

- SOC、SOH；
- 有功、无功；
- 直流电压、电流；
- 三相交流电压、电流和频率；
- 最高、最低和平均单体温度；
- 运行状态、控制模式、故障码和告警码；
- 今日及累计充放电量；
- 循环次数。

为控制闭环增加：

- `target_active_power`；
- `available_charge_power`；
- `available_discharge_power`；
- `bms_state`；
- `pcs_state`；
- `grid_connection_state`；
- `command_source`；
- `data_source`。

功率符号全链路统一：

```text
正功率 = 充电
负功率 = 放电
零功率 = 待机
```

### 7.4 调度计划

新增储能调度计划模型，至少包含：

- 调度日期、时段开始时间和 15 分钟间隔；
- 计划目标功率；
- 预测负荷、预测光伏和分时电价；
- 预计 SOC；
- 策略类型、策略版本和求解状态；
- 优化生成时间；
- 计划是否有效；
- 失败或回退原因。

计划记录与实际遥测分开存储，不用实际遥测覆盖计划值。

## 8. MQTT 契约

### 8.1 遥测

优先使用：

```text
campus/device/STO-001/telemetry
```

遥测消息至少包含设备身份、时间戳、SOC、实际有功、运行状态和数据来源。扩展字段按 `StorageTelemetry` 契约发送。

### 8.2 控制命令

沿用现有控制主题：

```text
campus/control/STO-001
```

第一阶段支持：

- `set_active_power`；
- `set_control_mode`；
- `stop`。

每条命令必须包含唯一 `command_id`、来源、原因和时间戳。平台发布成功只表示命令已经发送，不表示设备执行成功。

### 8.3 控制回执

沿用现有入站主题和 `message_type=control_receipt` 识别方式，不新增专用回执 topic。标准状态为：

- `accepted`；
- `running`；
- `success`；
- `failed`；
- `timeout`；
- `rejected`。

对于功率命令，`success` 表示实际功率进入目标允许偏差并保持规定时间。设备因 SOC、温度、故障、并网状态或模式限制无法执行时返回 `rejected`。重复命令和重复终态回执必须幂等处理。

## 9. 电池系统级仿真

### 9.1 园区功率平衡

采用：

```text
P_grid = P_load - P_pv + P_storage
```

其中 `P_storage > 0` 表示充电，`P_storage < 0` 表示放电。

### 9.2 SOC 演化

每个仿真步按充放电效率更新 SOC：

```text
SOC_next = SOC_now
  + [eta_charge * max(P_storage, 0)
  - max(-P_storage, 0) / eta_discharge]
  * delta_t / E_rated * 100%
```

SOC 数值必须限制在 0%～100%，控制动作受 10%～90% 安全范围约束。

### 9.3 功率执行

实际功率同时受以下限制：

- 目标功率；
- PCS 额定功率；
- BMS 可充、可放功率；
- 当前 SOC 与剩余能量；
- 温度和设备状态；
- 并网状态；
- 功率爬坡限制。

默认功率爬坡上限为每秒 25 kW，可配置。相反方向切换必须先经过待机，禁止瞬间由满功率充电切为满功率放电。

### 9.4 温度与寿命

第一版使用可解释的系统级近似：

- 温度随环境温度、功率绝对值和冷却能力变化；
- 温度达到预警值时降额，达到保护值时停机；
- 等效循环次数按累计能量吞吐计算；
- SOH 变化使用可配置的简化循环衰减参数。

这些参数仅用于仿真，不宣称代表具体电芯或厂商设备。

## 10. 安全联锁

硬联锁优先于所有调度目标：

| 条件 | 动作 |
| --- | --- |
| SOC ≤ 10% | 禁止放电 |
| SOC ≥ 90% | 禁止充电 |
| SOC ≤ 15% | 低 SOC 预警 |
| SOC ≥ 85% | 高 SOC 预警 |
| 温度进入预警区间 | 功率降额 |
| 温度达到保护值 | 停止充放电 |
| BMS 或 PCS 故障 | 立即停止 |
| 通信超时 | 目标功率清零并进入安全待机 |
| 并网断开 | 禁止普通并网充放电 |
| 手动模式 | 停止自动调度命令 |

阈值均来自配置或资产档案，不作为所有真实电池的通用安全标准。SOC、温度和需量阈值设置回差，避免在边界附近反复启停。

## 11. 实时规则控制

规则优先级为：

```text
安全保护 > 光伏富余吸收 > 需量削峰 > 峰谷电价 > 待机
```

### 11.1 光伏富余吸收

当光伏大于园区负荷时，以富余光伏和可充电功率的较小值充电。

### 11.2 需量削峰

当预计电网购电超过需量目标时，以超出量和可放电功率的较小值放电，使电网购电靠近目标。

### 11.3 峰谷电价

- 谷价时充电至计划 SOC；
- 峰价时在保留后续高峰 SOC 的前提下放电；
- 平价时原则上待机；
- 光伏消纳和需量削峰优先于简单峰谷套利。

### 11.4 防振荡

至少实现：

- 5 kW 功率死区；
- 最短充放电运行时间；
- 最短停机时间；
- SOC、温度和需量阈值回差；
- 功率变化速率限制；
- 相反方向切换前待机。

## 12. 日前优化调度

### 12.1 输入和时域

每天根据未来 24 小时的负荷、光伏、电价、初始 SOC 和设备能力，生成 96 个 15 分钟计划点。第一版使用可重复的历史或合成预测曲线，不把机器学习预测纳入范围。

### 12.2 决策与约束

决策变量包括充电功率、放电功率、电网购电功率、SOC、充放电状态和最大需量。约束至少包含：

- 各时段功率平衡；
- 充放电功率上限；
- 禁止同时充电和放电；
- SOC 演化；
- 15%～85% 优化软范围；
- 日末 SOC 目标；
- 最大需量定义；
- 第一版不允许向电网反送电。

### 12.3 目标函数

综合最小化：

- 分时购电成本；
- 最大需量成本；
- 电池能量吞吐折损成本；
- 光伏弃电惩罚。

第一版使用 PuLP 和 CBC 求解混合整数线性模型，不依赖商业求解器。

### 12.4 实时执行与回退

日前优化器只提供计划。实时 EMS 每分钟根据实际 SOC、负荷、光伏、温度、BMS/PCS、并网和通信状态校验并修正目标功率。

优化无解、超时或输入缺失时：

1. 不发布异常计划；
2. 在有效期内保留最近有效计划；
3. 无有效计划时回退到规则控制；
4. 页面显示求解和回退状态；
5. 记录失败原因和告警。

本设计称为“日前优化 + 实时规则执行”，不称为 MPC；只有未来实现持续重求解、反馈校正和明确滚动时域后，才评估是否使用滚动优化或 MPC 术语。

## 13. 页面设计

### 13.1 光储运行总览

展示：

- 光伏、负荷、电网和储能之间的实时能量流；
- 负荷、光伏、电网购电、计划功率、实际功率和 SOC 主趋势；
- 当前电价、策略和控制来源；
- 今日成本、最大需量、光伏自用率和弃光量。

### 13.2 储能设备工作台

包含：

- SOC、SOH、目标/实际功率和可充放电能力；
- BMS、PCS、并网和运行状态；
- 直流、三相交流、频率和温度；
- 手动/自动模式、功率设置和停止；
- 命令状态与回执时间线；
- 告警、故障和事件。

### 13.3 调度与收益

展示：

- 负荷、光伏和电价预测；
- 计划功率、预计 SOC 和实际偏差；
- 无储能、规则控制和日前优化对比；
- 成本、需量、光伏自用率、弃光和等效循环；
- 求解成功、使用旧计划、规则回退或输入缺失状态。

### 13.4 场景控制

支持选择固定场景、仿真速度和故障注入。故障注入必须明确标记，并允许恢复到正常状态。

## 14. 演示场景

固定演示覆盖：

1. 午间光伏富余：自动充电、SOC 上升、弃光下降。
2. 晚高峰削峰：自动放电、电网购电压到需量目标附近。
3. SOC 下限：放电命令被拒绝并产生低 SOC 告警。
4. 温度保护：先降额，再停止，最后恢复。
5. 控制闭环：展示 `accepted -> running -> success`。
6. 控制异常：展示 `rejected`、`failed` 或 `timeout`。
7. 调度对比：同一输入下比较无储能、规则控制和日前优化。

建议制作一个 5 分钟固定演示视频，并保留可现场操作的一键启动版本。

## 15. 量化指标

每个完整仿真日输出：

- 购电成本；
- 最大电网购电功率；
- 光伏自用率；
- 弃光量；
- 峰谷差；
- 充电量与放电量；
- 往返效率；
- 等效循环次数；
- 日末 SOC；
- 计划执行率；
- 控制命令成功、拒绝和超时数量。

对比结果必须由同一输入场景自动计算，不在页面中硬编码节省比例或改善幅度。

## 16. 错误处理与可观测性

- MQTT 遥测校验失败进入现有接入流水，记录失败原因并支持重放。
- 遥测过期、重复和时间戳异常沿用现有接入规则。
- 命令发布、设备执行和回执分别记录，不能把发布成功当成执行成功。
- 控制命令到期后自动转为 `timeout`。
- 重复终态回执保持幂等；迟到回执不覆盖已确认终态。
- 自动和手动控制发生冲突时，手动接管优先且自动控制暂停。
- 仿真器异常退出后，平台将设备标记为通信异常，实时 EMS 清零目标功率。
- 优化器失败不影响基础监控和规则控制。
- 页面所有缺失值显示为空态，不生成看似真实的占位数据。

- `command_id` 关联与幂等；
- API、WebSocket 和前端类型一致性；
- 计划与实际数据分离。

### 17.3 集成测试

- 仿真器到 MQTT、数据库、API 和页面的遥测链路；
- 平台到仿真 PCS 再返回回执的控制链路；
- SOC/温度保护触发、持续和恢复；
- 优化计划生成、实时执行和规则回退；
- 同一场景下三种策略的结果对比。

### 17.4 验收门槛

- SOC 不越过物理范围，控制不越过安全范围；
- 实际功率不超过可用功率与 PCS 额定功率；
- 日累计充放电量与功率积分在允许误差内一致；
- 96 时段计划功率平衡成立；
- 不发生同一时段同时充电和放电；
- 日末 SOC 达到配置目标；
- 命令生命周期可追溯且超时可收敛；
- 缺失和仿真数据来源在页面清晰可见；
- 演示场景可重复运行并输出自动报告。

## 18. 实施阶段建议

设计批准后的实施计划应拆为以下阶段，每阶段独立验收：

1. 契约与资产层：储能资产档案、遥测补充字段、迁移和契约测试。
2. 仿真核心：场景、电池、BMS、PCS 和 MQTT 遥测。
3. 控制闭环：命令服务、回执、超时、幂等和手自动切换。
4. 规则 EMS：安全联锁、光伏消纳、削峰和峰谷策略。
5. 页面增强：总览、工作台、场景控制、命令时间线。
6. 日前优化：96 时段模型、计划存储、回退和收益对比。
7. 演示与验收：固定场景、自动报告、文档、视频和一键启动。

由于仓库当前主主题仍是后端可靠性阶段 2A，正式实施前必须由规则角色决定新主题切换或排期，不在当前可靠性主题中顺手修改生产代码。涉及新增数据库结构时，必须服从阶段 2A Alembic 链可信化后的迁移规则。

## 19. 后续真实硬件接入

第二阶段接真实设备时：

- 保持 `device_category=storage` 和稳定 MQTT 应用层契约；
- 由网关将 Modbus、CAN、IEC 61850 或厂商协议转换为平台字段；
- 将仿真 BMS/PCS 替换为真实适配器；
- 重新确认厂商功率方向、SOC、温度、告警和保护语义；
- 真实控制必须增加权限、审批、联锁和现场急停边界；
- 所有阈值改为厂商与现场配置，不沿用仿真默认值；
- 在真实设备验证前，不将仿真回执口径描述为厂商正式协议。

## 20. 对外表述边界

完成第一阶段后，简历可描述为：

> 独立设计园区光储协同 EMS，构建 500 kWh/250 kW 储能系统级仿真器，通过 MQTT 实现 BMS/PCS 遥测、功率控制与回执闭环；设计 SOC、温度及通信安全联锁，并建立考虑分时电价、最大需量、光伏消纳和电池折损的 96 时段日前调度模型。

必须同时明确第一阶段为系统级仿真，不描述为真实储能电站、真实 BMS/PCS 接入、电池电化学仿真或电网稳定性控制。
