# 单一储能系统扩展与模拟转真实收敛设计

## 1. 文档状态

- 日期：2026-07-17
- 状态：设计对话已确认，等待用户复核书面规格
- 适用主题：园区光储协同仿真与 EMS 控制
- 约束等级：后续 PLAN、详细实施计划、状态与交接必须遵循

本文收敛 `2026-07-16-campus-pv-storage-simulation-design.md` 中的数据源定位、页面落点和真实设备切换方式。原设计其余已确认的电池模型、安全联锁、控制回执、日前优化及收益口径继续有效；与本文冲突的内容以本文为准。

## 2. 核心决策

项目只保留一个储能业务系统：

- 一个储能设备模型和设备身份体系；
- 一套储能资产档案、遥测、调度计划和控制日志；
- 一组 `/devices/{id}/storage/...` 业务接口；
- 一个原有储能设备监控与控制页面；
- 一套规则 EMS、日前调度和收益分析服务；
- 模拟器与未来厂商网关只是可替换的数据源，不是两套储能业务系统。

模拟阶段没有真实设备数据。模拟器先通过未来真实设备也必须遵循的标准 MQTT 契约接入原系统；真实设备上线时停止模拟器、限定范围清理模拟数据，并用厂商网关替换模拟器。监控页面、业务 API、控制服务和分析逻辑不因数据源替换而重做。

## 3. 总体架构

```text
当前：储能模拟器 ─┐
                  ├─ 标准储能 MQTT 契约 ─ 原有接入链 ─ 单一储能业务系统
未来：厂商网关 ───┘                                      ├─ 原储能设备页
                                                        └─ 能耗分析页的光储 EMS 页签
```

平台内部不直接兼容每个厂商的 Modbus、CAN、IEC 61850 或私有字段。未来由设备侧网关负责协议转换，并输出平台稳定 MQTT 契约。厂商差异不得渗透到监控页面、调度服务或收益分析服务。

## 4. 已完成成果的归属

现有 Task 1 至 Task 5 不推倒重做：

| 已完成内容 | 在单一系统中的定位 | 结论 |
| --- | --- | --- |
| 纯电池状态模型 | 模拟器状态演化与策略回放核心 | 保留 |
| `StorageAssetProfile` | 同一储能设备的能力与安全档案 | 保留 |
| `StorageTelemetry` 扩展 | 同一储能设备的专属遥测 | 保留 |
| `StorageDispatchPlan` | 同一储能设备的日前计划 | 保留 |
| MQTT 扩展解析与状态映射 | 标准储能 MQTT 接入层 | 保留 |
| 监控服务扩展 | 原储能设备页的数据源 | 保留 |
| 五场景 MQTT 模拟器 | 当前临时设备侧适配器 | 保留并收敛定位 |
| `data_source=simulated` | 模拟阶段来源与清理依据 | 保留 |

模拟器的容量、功率、SOC 边界和效率最终应来自 `StorageAssetProfile` 或由该档案生成的明确启动配置。500 kWh/250 kW 只是当前演示默认值，不得在设备页、控制服务或优化器中形成第二套参数来源。

## 5. 单设备页面扩展

继续使用原有 `StorageMonitorView`、设备路由、权限和刷新机制，不新增模拟版监控页面。

### 5.1 顶部状态

- 设备名称、编号、在线状态和最近遥测时间；
- `模拟数据` 或 `真实设备` 来源标识；
- 手动/自动控制模式；
- EMS 自动控制授权状态；
- BMS、PCS 和并网状态汇总。

### 5.2 实时监控

- SOC、SOH、实际功率和目标功率；
- 目标与实际功率偏差；
- 可充电功率和可放电功率；
- 电芯温度、循环次数、故障码和告警码；
- 当前命令来源：人工、规则 EMS 或日前计划；
- 当前计划时段及计划功率。

功率符号始终为正功率充电、负功率放电。

### 5.3 控制与回执

- 手动/自动模式切换；
- 设置目标有功功率；
- 停止充放电；
- 命令生命周期：`accepted -> running -> success/failed/timeout/rejected`；
- 自动控制授权仅向有权限的管理员开放；
- 模拟场景与故障注入只在仿真门禁开启时显示，真实切换后隐藏。

### 5.4 趋势和异常

- 实际功率与目标功率双曲线；
- SOC、温度及可充放能力趋势；
- 计划功率与实际功率对比；
- SOC/温度越限、BMS/PCS 故障、并网断开、遥测超时、命令超时及功率偏差告警。

## 6. 园区级分析页面

不新增独立 `/storage-energy` 页面。光伏、负荷、电网和储能的园区级联动进入现有“能耗分析”页面的新“光储 EMS”页签。

该页签包含：

- 光伏、负荷、电网和储能能量流；
- 负荷、光伏、计划功率、实际功率和 SOC 主趋势；
- 96 时段日前计划与执行偏差；
- 固定场景选择和策略回放；
- 无储能、规则控制、日前优化三种策略对比；
- 电费、最大需量、光伏自用率、弃光量、吞吐量和等效循环。

设备页负责单设备状态和控制，能耗分析页负责园区级协同和收益；两者使用同一后端储能领域服务，不复制计算逻辑。

## 7. 标准设备契约

### 7.1 遥测

统一使用：

```text
campus/device/{device_code}/telemetry
```

核心字段包括设备编号、时间戳、SOC、SOH、实际/目标功率、可充/可放功率、BMS/PCS/并网状态、温度、故障/告警码、控制模式、命令来源和数据来源。

`data_source` 在模拟阶段必须为 `simulated`；真实网关接入后必须为 `real`。平台不得根据设备编号或页面状态猜测数据来源。

### 7.2 控制与回执

控制主题继续使用：

```text
campus/control/{device_code}
```

只支持 `set_active_power`、`set_control_mode` 和 `stop`。模拟场景控制使用单独的 simulation-only topic，不能通过真实设备控制主题注入场景或故障。

平台发布 MQTT 成功只表示命令已发送。设备执行结果必须由标准回执确认，并具备幂等、超时和迟到回执处理。

## 8. 自动控制安全边界

- EMS 自动控制全局和单设备均默认关闭；
- 每台设备完成能力确认、安全验收和控制回执验证后，由管理员单独启用；
- SOC、温度、BMS/PCS 故障、并网和通信状态优先于人工以外的所有策略；
- 遥测过期时禁止自动下发新功率；
- 同一设备同一时间只允许一个执行中的控制命令；
- 人工接管优先，并暂停当前自动计划；
- 真实设备阈值必须来自厂商和现场配置，不直接沿用仿真默认值。

## 9. 模拟转真实流程

真实设备上线时执行受控切换：

1. 关闭该设备 EMS 自动控制；
2. 停止模拟器并确认不再上报；
3. 记录切换操作人、设备、时间和清理范围；
4. 只删除该设备的全部模拟业务数据：以 `StorageTelemetry.data_source=simulated` 识别遥测，并为遥测保留可选 `simulation_run_id`；后续为 `StorageDispatchPlan` 增加同名来源与运行标识字段；储能控制日志在结构化 `reason` 中固定记录 `data_source` 和 `simulation_run_id`，并同时限定 `command_source=storage-control-api`；
5. 保留设备档案、权限、页面配置、标准接口和安全设置；
6. 接入厂商网关并验证 `data_source=real` 遥测；
7. 验证状态、控制、回执、超时和急停边界；
8. 完成现场安全验收后，由管理员启用自动控制。

清理必须通过专用服务或脚本按精确设备和来源执行，禁止清空整张遥测表，禁止影响其他设备。切换前应生成遥测、计划和控制记录的分类数量预览；执行后保留一条不参与业务展示的清理审计事件。这里的“清空模拟数据”指清除该设备的模拟业务记录，不删除切换审计证据。

## 10. 错误处理与可观测性

- 遥测格式错误进入现有 MQTT 失败流水并保留重放能力；
- 来源缺失或非法时拒绝进入正式储能遥测；
- 设备能力、实际 payload 与页面类型不一致时记录契约错误；
- 自动控制被安全条件阻止时返回稳定原因码；
- 命令发送、设备接受、执行中和终态分别记录；
- 优化失败时保留基础监控，按规则 EMS 回退；
- 页面缺失值显示 `--`，不得生成伪造占位数据；
- 模拟数据在设备页和能耗分析页持续显示来源标识。

## 11. 测试与验收

### 11.1 契约复用

同一组标准 MQTT 契约测试必须能验证模拟器和未来厂商网关适配器。数据源替换不得要求修改设备页或业务 API 测试。

### 11.2 核心验收

- 模拟器通过标准契约驱动原有设备页；
- 原有储能历史、告警、权限和路由无回归；
- 仿真与真实来源不能混淆；
- 功率符号在遥测、控制、计划、API 和页面中一致；
- 安全拒绝、重复命令、回执超时和人工接管可复现；
- 清理预览与执行只影响指定设备的模拟记录；
- 停止模拟器并接入符合契约的替代适配器后，页面和业务接口不修改即可工作；
- 园区级策略对比使用同一输入序列，不硬编码收益改善。

## 12. 后续计划收敛规则

现有详细计划按以下原则修订，不新增第二份并行实施计划：

- Task 1 至 Task 5 保留完成状态，只补充其在单一系统中的正式定位；
- Task 6 至 Task 9 继续完成控制回执、规则 EMS、自动任务与 API，但只扩展现有储能服务；
- Task 10 只增强原有 `StorageMonitorView`，不创建模拟版页面；
- Task 11 至 Task 13 继续完成日前优化和园区级聚合，计算逻辑保持单一来源；
- Task 14 改为在现有能耗分析页面增加“光储 EMS”页签，不新增 `/storage-energy` 路由；
- Task 15 增加受控模拟数据清理与可替换适配器验收；
- `current-status.md`、`handoff.md` 和每日快照只引用同一个当前任务和同一份详细计划；
- 原计划中任何“独立模拟储能系统、独立模拟设备页面、独立光储路由”的表述全部删除或改写。

## 13. 非目标

- 不维护模拟版与真实版两套储能业务系统；
- 不让后端直接耦合具体厂商私有协议；
- 不在真实设备验收前默认开启自动控制；
- 不把系统级模拟器描述为真实 BMS/PCS 固件；
- 不在本主题中实现电化学、PCS 底层电流环、配电网潮流或继电保护；
- 不为收敛计划而重写已通过验收的 Task 1 至 Task 5 实现。

## 14. 完成定义

当以下条件同时满足时，单一储能系统扩展完成：

1. 模拟器通过标准 MQTT 契约驱动原有储能设备页面和控制闭环；
2. 原有设备页具备完整监控、控制、回执和安全状态；
3. 能耗分析页具备光储 EMS、日前计划和策略收益页签；
4. 自动控制默认关闭并可按设备安全启用；
5. 模拟数据可按设备预览并安全清理；
6. 符合标准契约的厂商网关可替换模拟器，而无需修改储能业务层与页面。
