## 📊 整合前后对比

### 整合前（问题）
```
MineEnergySystem/
├── README.md                           # 主文档
├── CHANGELOG_MAC.md                    # Mac 适配日志
├── STARTUP_FLOW.md                     # 启动流程详解
├── STARTUP_OPTIMIZATION.md             # 启动优化指南
├── TROUBLESHOOTING.md                  # 故障排查
├── WEBSOCKET_FIX.md                    # WebSocket 修复
├── HEALTH_CHECK_GUIDE.md               # 健康检查指南
├── HEALTH_CHECK_IMPLEMENTATION.md      # 健康检查实施
├── NEXT_STEPS.md                       # 下一步计划
├── PROJECT_ROADMAP.md                  # 项目路线图
└── README_SCRIPTS.md                   # 脚本说明
```

**问题**:
- ❌ 文档分散，信息难以查找
- ❌ 内容重复，维护成本高
- ❌ 用户体验差，需要在多个文档间切换
- ❌ 更新困难，容易遗漏

### 整合后（优势）
```
MineEnergySystem/
├── README.md                    # ✨ 统一主文档（包含所有信息）
├── docs/
│   └── archive/                # 📦 归档目录（保留历史文档）
│       ├── README_ARCHIVE.md   # 归档说明
│       ├── CHANGELOG_MAC.md
│       ├── STARTUP_FLOW.md
│       ├── TROUBLESHOOTING.md
│       └── ... (其他归档文档)
└── app/
    └── README.md               # 代码结构说明（保留）
```

**优势**:
- ✅ 统一入口，一个文档包含所有信息
- ✅ 结构清晰，按功能模块组织
- ✅ 易于维护，只需更新一个文件
- ✅ 用户体验好，快速找到所需信息

## 🔄 后续维护策略

### 文档更新原则
1. **主文档优先** - 所有更新都在 `README.md` 中进行
2. **归档不更新** - `docs/archive/` 中的文档不再更新
3. **保持简洁** - 避免创建新的独立文档
4. **单一来源** - 维护唯一的真实信息源

### 新功能文档
当添加新功能时：
1. 直接在 `README.md` 相应章节中更新
2. 如果是小功能，添加到现有章节
3. 如果是大功能，可添加新的二级标题
4. 不要创建独立的功能文档

### 代码文档
- `app/README.md` - 继续维护，说明代码结构
- API 文档 - 通过 FastAPI 自动生成（Swagger/ReDoc）
- 函数注释 - 在代码中维护
