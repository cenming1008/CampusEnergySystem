# 多对多关系详解

## 📚 什么是多对多关系？

### 生活中的例子

**学生和课程的关系：**
```
学生小明 ← 选修 → 数学课
学生小明 ← 选修 → 英语课
学生小明 ← 选修 → 物理课

学生小红 ← 选修 → 数学课
学生小红 ← 选修 → 英语课

学生小刚 ← 选修 → 物理课
```

**特点：**
- 一个学生可以选多门课
- 一门课可以被多个学生选
- 这就是"多对多"关系

### 设备和分组的关系

```
设备A ← 属于 → 关键设备组
设备A ← 属于 → 生产设备组

设备B ← 属于 → 关键设备组
设备B ← 属于 → 备用设备组

设备C ← 属于 → 办公设备组
```

**特点：**
- 一个设备可以属于多个分组（如：既是关键设备，又是生产设备）
- 一个分组可以包含多个设备
- 这就是多对多关系

---

## 🔍 数据库中如何实现多对多？

### ❌ 错误方式1：在设备表中存储分组ID

```python
# ❌ 这样做不行！
class Device(SQLModel, table=True):
    id: int
    name: str
    group_id: int  # 只能存一个分组！
```

**问题：**
- 一个设备只能属于一个分组
- 无法实现"设备A既属于关键设备组，又属于生产设备组"

### ❌ 错误方式2：存储分组ID列表（字符串）

```python
# ❌ 这样勉强可以，但不好
class Device(SQLModel, table=True):
    id: int
    name: str
    group_ids: str  # "1,2,3"  存储为字符串
```

**问题：**
- 无法使用外键约束（无法保证分组ID存在）
- 查询困难（需要字符串解析和模糊查询）
- 性能差
- 不规范

### ✅ 正确方式：使用中间表（关联表）

```python
# 表1：设备表
class Device(SQLModel, table=True):
    id: int
    name: str

# 表2：分组表
class DeviceGroup(SQLModel, table=True):
    id: int
    name: str

# 表3：中间表（关联表）
class DeviceGroupMembership(SQLModel, table=True):
    device_id: int      # 指向设备
    group_id: int       # 指向分组
    joined_at: datetime # 额外信息
```

## 🎯 代码详解

### 完整的三张表

```python
# 表1：设备表
class Device(SQLModel, table=True):
    """设备表"""
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str
    sn: str
    # ... 其他字段


# 表2：设备分组表
class DeviceGroup(SQLModel, table=True):
    """设备分组表"""
    __tablename__ = "device_group"
    
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(description="分组名称")
    description: Optional[str] = None
    # ... 其他字段


# 表3：关联表（中间表）★ 这是关键！
class DeviceGroupMembership(SQLModel, table=True):
    """设备-分组关联表（多对多）"""
    
    __tablename__ = "device_group_membership"
    
    # 联合主键（两个字段一起作为主键）
    device_id: int = Field(primary_key=True, foreign_key="device.id")
    group_id: int = Field(primary_key=True, foreign_key="device_group.id")
    
    # 额外信息（可选）
    joined_at: datetime = Field(default_factory=datetime.now)
    note: Optional[str] = Field(default=None, description="备注")
```

---

## 🔧 关键点解析

### 1. 联合主键（Composite Primary Key）

```python
device_id: int = Field(primary_key=True, foreign_key="device.id")
group_id: int = Field(primary_key=True, foreign_key="device_group.id")
```

**含义：**
- `primary_key=True` 表示这是主键
- 两个字段都是主键 → **联合主键**
- 联合主键保证：同一个设备不能重复加入同一个分组

**数据示例：**
```
device_id | group_id | joined_at
----------|----------|------------------
1         | 1        | 2026-01-24 10:00
1         | 2        | 2026-01-24 10:01  ✅ 允许（设备1加入分组2）
2         | 1        | 2026-01-24 10:02  ✅ 允许（设备2加入分组1）
1         | 1        | 2026-01-24 10:03  ❌ 不允许（重复！）
```

### 2. 外键约束（Foreign Key）

```python
foreign_key="device.id"       # 指向 device 表的 id 字段
foreign_key="device_group.id" # 指向 device_group 表的 id 字段
```

**作用：**
- ✅ 保证数据完整性（引用的设备/分组必须存在）
- ✅ 级联删除（可选配置）
- ✅ 防止数据孤儿

**示例：**
```python
# ✅ 正确：设备1和分组1都存在
DeviceGroupMembership(device_id=1, group_id=1)

# ❌ 错误：设备999不存在，数据库会拒绝插入
DeviceGroupMembership(device_id=999, group_id=1)  # 外键约束失败
```

### 3. 额外字段（可选）

```python
joined_at: datetime = Field(default_factory=datetime.now)
note: Optional[str] = Field(default=None, description="备注")
```

**用途：**
中间表不仅可以存储关系，还可以存储**关系的属性**：
- `joined_at`: 什么时候加入的？
- `note`: 为什么加入？有什么备注？
- 其他可能的字段：`priority`（优先级）、`added_by`（操作人）等

## 🎨 完整的服务层实现

### DeviceGroupService 示例

```python
class DeviceGroupService:
    """设备分组服务"""
    
    @staticmethod
    def add_device_to_group(
        session: Session,
        device_id: int,
        group_id: int,
        note: Optional[str] = None
    ):
        """将设备加入分组"""
        # 检查设备是否存在
        device = session.get(Device, device_id)
        if not device:
            raise ValueError(f"设备 {device_id} 不存在")
        
        # 检查分组是否存在
        group = session.get(DeviceGroup, group_id)
        if not group:
            raise ValueError(f"分组 {group_id} 不存在")
        
        # 检查是否已经在分组中
        existing = session.exec(
            select(DeviceGroupMembership).where(
                DeviceGroupMembership.device_id == device_id,
                DeviceGroupMembership.group_id == group_id
            )
        ).first()
        
        if existing:
            raise ValueError("设备已经在该分组中")
        
        # 创建关联
        membership = DeviceGroupMembership(
            device_id=device_id,
            group_id=group_id,
            note=note
        )
        session.add(membership)
        session.commit()
        
        return membership
    
    @staticmethod
    def get_device_groups(session: Session, device_id: int):
        """获取设备所属的所有分组"""
        statement = (
            select(DeviceGroup)
            .join(DeviceGroupMembership)
            .where(DeviceGroupMembership.device_id == device_id)
        )
        return list(session.exec(statement).all())
    
    @staticmethod
    def get_group_devices(session: Session, group_id: int):
        """获取分组包含的所有设备"""
        statement = (
            select(Device)
            .join(DeviceGroupMembership)
            .where(DeviceGroupMembership.group_id == group_id)
        )
        return list(session.exec(statement).all())
    
    @staticmethod
    def remove_device_from_group(
        session: Session,
        device_id: int,
        group_id: int
    ):
        """将设备从分组中移除"""
        membership = session.exec(
            select(DeviceGroupMembership).where(
                DeviceGroupMembership.device_id == device_id,
                DeviceGroupMembership.group_id == group_id
            )
        ).first()
        
        if not membership:
            raise ValueError("设备不在该分组中")
        
        session.delete(membership)
        session.commit()
```

## 🆚 对比：一对多 vs 多对多

### 一对多关系（不需要中间表）

```python
# 一个设备只能有一个位置
class Device(SQLModel, table=True):
    id: int
    name: str
    location_id: int = Field(foreign_key="location.id")  # 直接存储外键
```

**特点：**
- 一个设备 → 一个位置 ✅
- 一个位置 → 多个设备 ✅
- 直接用外键字段即可

### 多对多关系（必须用中间表）

```python
# 设备表
class Device(SQLModel, table=True):
    id: int
    name: str
    # ❌ 不能直接存储 group_id

# 分组表
class DeviceGroup(SQLModel, table=True):
    id: int
    name: str
    # ❌ 不能直接存储 device_id

# ✅ 需要中间表
class DeviceGroupMembership(SQLModel, table=True):
    device_id: int = Field(primary_key=True, foreign_key="device.id")
    group_id: int = Field(primary_key=True, foreign_key="device_group.id")
```

**特点：**
- 一个设备 → 多个分组 ✅
- 一个分组 → 多个设备 ✅
- 必须用中间表

## 📝 SQL 查询对比

### 不用中间表（一对多）

```sql
-- 查询设备及其位置（简单JOIN）
SELECT device.*, location.name as location_name
FROM device
JOIN location ON device.location_id = location.id;
```

### 用中间表（多对多）

```sql
-- 查询设备及其所有分组（需要两次JOIN）
SELECT device.name, device_group.name as group_name
FROM device
JOIN device_group_membership ON device.id = device_group_membership.device_id
JOIN device_group ON device_group_membership.group_id = device_group.id;
```

## 🎓 总结

### 多对多关系的核心要点

| 要点 | 说明 |
|------|------|
| **为什么需要中间表** | 因为两边都是"多"，无法用单个外键表示 |
| **中间表的作用** | 存储两个表的ID对应关系 |
| **联合主键** | 防止重复关联（同一对关系只能存在一次） |
| **外键约束** | 保证引用的记录存在 |
| **额外字段** | 可以存储关系的属性（如加入时间、备注） |

### 记忆口诀

```
多对多关系要实现，
中间表来做桥梁。
两个外键联合键，
存储关系不会乱。

一个设备多个组，
一个组有多设备。
关联表中记录全，
查询统计都方便！
```

### 实际应用场景

✅ **适合用多对多的场景：**
- 设备 ↔ 分组（一个设备可以属于多个分组）
- 学生 ↔ 课程（一个学生选多门课，一门课有多个学生）
- 用户 ↔ 角色（一个用户有多个角色，一个角色给多个用户）
- 文章 ↔ 标签（一篇文章有多个标签，一个标签用于多篇文章）

❌ **不适合用多对多的场景：**
- 设备 ↔ 位置（一个设备只能在一个位置）→ 用一对多
- 订单 ↔ 用户（一个订单只属于一个用户）→ 用一对多
