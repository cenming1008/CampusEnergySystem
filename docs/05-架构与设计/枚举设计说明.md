# 枚举设计说明 - 为什么使用枚举？

## 对比示例

### ❌ 不使用枚举（容易出错）

```python
# 创建设备时，可能会拼写错误
device1 = Device(name="水表1", device_category="water_metter")  # 拼错了！
device2 = Device(name="水表2", device_category="watermeter")    # 少了下划线
device3 = Device(name="水表3", device_category="WATER_METER")   # 大写了
device4 = Device(name="水表4", device_category="水表")          # 用了中文

# 查询时也会出错
devices = session.exec(
    select(Device).where(Device.device_category == "water_meter")
).all()  # 只能查到正确拼写的，其他3个查不到！

# 结果：数据库中有4个水表，但查询只返回1个 ❌
```

**问题：**
- ❌ 拼写错误无法在编写代码时发现
- ❌ IDE 无法提供代码提示
- ❌ 数据库中会有多种不一致的值
- ❌ 查询和统计结果不准确

### ✅ 使用枚举（安全可靠）

```python
# 定义枚举
class DeviceCategory(str, Enum):
    WATER_METER = "water_meter"
    GAS_METER = "gas_meter"

# 创建设备，IDE会自动提示
device1 = Device(name="水表1", device_category=DeviceCategory.WATER_METER)  # ✅
device2 = Device(name="水表2", device_category=DeviceCategory.WATER_METER)  # ✅

# 如果拼错，IDE会立即报错
device3 = Device(name="水表3", device_category=DeviceCategory.WATER_METTER)  
# ❌ IDE提示：DeviceCategory 没有 WATER_METTER 属性

# 查询时也使用枚举
devices = session.exec(
    select(Device).where(Device.device_category == DeviceCategory.WATER_METER)
).all()  # 能查到所有水表 ✅

# 结果：数据一致，查询准确 ✅
```

## 🎯 使用枚举的6大好处

### 1. ✅ 防止拼写错误

```python
# ❌ 不用枚举：手动输入，容易拼错
device_type = "water_metter"  # 拼错了！数据库会存入错误值

# ✅ 用枚举：IDE自动提示，不会拼错
device_type = DeviceCategory.WATER_METER  # IDE提示所有可选值
```

### 2. ✅ IDE 智能提示

```python
# 输入 DeviceCategory. 后，IDE会自动列出所有选项：
# - LOAD
# - SOLAR
# - WIND
# - WATER_METER
# - GAS_METER
# - ...

# 不需要记住所有设备类型，IDE帮你记住！
```

### 3. ✅ 类型检查

```python
def create_device(category: DeviceCategory):  # 参数类型是枚举
    pass

# ✅ 正确使用
create_device(DeviceCategory.SOLAR)

# ❌ 错误使用，IDE会提示类型错误
create_device("solar")  # 类型不匹配！
```

### 4. ✅ 集中管理，便于维护

```python
# 如果要新增一个设备类型，只需要在枚举中添加一行
class DeviceCategory(str, Enum):
    LOAD = "load"
    SOLAR = "solar"
    WIND = "wind"
    # 新增：电动汽车充电桩
    EV_CHARGER = "ev_charger"  # ✅ 只改一个地方

# 所有使用这个枚举的地方都会自动支持新类型
```

### 5. ✅ 文档即代码

```python
class DeviceCategory(str, Enum):
    """设备类别枚举"""
    LOAD = "load"                # 用电设备
    SOLAR = "solar"              # 光伏发电
    WIND = "wind"                # 风力发电
    WATER_METER = "water_meter"  # 水表
    
# 看代码就知道系统支持哪些设备，不需要额外文档
```

### 6. ✅ 数据验证

```python
from app.services.maintenance_service import MaintenanceService
```

## 🔄 枚举与数据库表的关系

### 定义顺序

```python
# 1️⃣ 第一步：定义枚举（可选值）
class DeviceCategory(str, Enum):
    LOAD = "load"
    SOLAR = "solar"
    # ...

# 2️⃣ 第二步：定义表结构（使用枚举）
class Device(SQLModel, table=True):
    device_category: str = Field(
        default=DeviceCategory.LOAD,  # 使用枚举作为默认值
        description="设备类别"
    )
```

### 为什么要先定义枚举？

**因为 Python 的代码是从上往下执行的！**

```python
# ❌ 错误示例：使用未定义的枚举
class Device(SQLModel, table=True):
    device_category: str = Field(default=DeviceCategory.LOAD)  # 错误！
                                                                # DeviceCategory 还没定义

class DeviceCategory(str, Enum):  # 定义在后面
    LOAD = "load"

# 运行会报错：NameError: name 'DeviceCategory' is not defined
```

```python
# ✅ 正确示例：先定义枚举
class DeviceCategory(str, Enum):  # 先定义
    LOAD = "load"

class Device(SQLModel, table=True):
    device_category: str = Field(default=DeviceCategory.LOAD)  # 后使用
    # ✅ 正确！DeviceCategory 已经定义了
```

## 📊 数据库存储

### 枚举值如何存储到数据库？

```python
class DeviceCategory(str, Enum):
    WATER_METER = "water_meter"
```

**重要：** `(str, Enum)` 表示这是一个**字符串枚举**

- 在 Python 代码中：使用 `DeviceCategory.WATER_METER`
- 在数据库中：存储的是字符串 `"water_meter"`

```sql
-- 数据库中的实际存储
INSERT INTO device (name, device_category) 
VALUES ('水表1', 'water_meter');  -- 存储的是字符串值

-- 不是存储枚举名称！
-- ❌ 不是 'WATER_METER'
-- ✅ 是 'water_meter'
```

## 🎓 总结

### 枚举的作用

| 作用 | 说明 |
|------|------|
| 🛡️ 类型安全 | 防止拼写错误和无效值 |
| 💡 IDE 提示 | 自动提示所有可选值 |
| 📖 自文档化 | 看代码就知道有哪些选项 |
| 🔧 易维护 | 新增选项只需改一处 |
| ✅ 数据一致性 | 保证数据库值统一规范 |

### 为什么要先定义枚举？

1. **Python 语法要求**：必须先定义才能使用
2. **逻辑关系**：枚举定义"可选值"，表使用"可选值"
3. **最佳实践**：先定义约束，再定义结构

### 类比理解

把枚举想象成**菜单**，把表想象成**点菜**：

```
🍽️ 菜单（枚举）
- 🍜 面条
- 🍚 米饭  
- 🍔 汉堡

👤 顾客点菜（使用枚举）
- 我要 🍜 面条  ✅ 菜单上有
- 我要 🍕 披萨  ❌ 菜单上没有，不能点！
```

**必须先有菜单，才能点菜！**
