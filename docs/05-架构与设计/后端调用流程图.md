## 🔄 2. 核心业务流程

### 2.1 用户登录认证流程

```mermaid
sequenceDiagram
    participant C as 前端客户端
    participant API as auth.py
    participant Security as security.py
    participant DB as PostgreSQL
    
    C->>API: POST /auth/login<br/>{username, password}
    API->>DB: 查询用户<br/>SELECT * FROM user WHERE username=?
    DB-->>API: 返回用户记录<br/>{id, username, hashed_password}
    
    alt 用户不存在
        API-->>C: 401 认证失败
    else 用户存在
        API->>Security: verify_password()<br/>验证密码
        
        alt 密码错误
            Security-->>API: False
            API-->>C: 401 认证失败
        else 密码正确
            Security-->>API: True
            API->>Security: create_access_token()<br/>生成JWT令牌
            Security-->>API: JWT Token
            API-->>C: 200 OK<br/>{access_token, token_type}
        end
    end
    
    Note over C: 后续请求携带Token<br/>Authorization: Bearer <token>
```

### 2.2 设备数据上报完整流程（推荐）

```mermaid
sequenceDiagram
    participant IoT as IoT设备
    participant MQTT as MQTT Broker
    participant Worker as mqtt_worker.py
    participant DS as DeviceService
    participant ES as EnergyService
    participant AS as AlarmService
    participant DB as PostgreSQL
    participant WS as WebSocket Manager
    participant Client as 前端客户端
    
    IoT->>MQTT: PUBLISH mine/device/001/telemetry<br/>{device_code: "001", voltage: 220, ...}
    MQTT->>Worker: on_message 回调
    
    Worker->>Worker: 解析消息<br/>JSON decode
    Worker->>DB: 根据device_code查询device_id
    DB-->>Worker: device_id = 1
    
    Worker->>DS: report_device_data()<br/>(device_id=1, data={...})
    
    DS->>DB: 获取设备信息<br/>SELECT * FROM device WHERE id=1
    DB-->>DS: device对象<br/>{id:1, device_type:"load", energy_type:"electricity"}
    
    DS->>DS: 从DeviceRegistry获取配置<br/>验证必需字段
    
    DS->>ES: save_energy_data()<br/>(device_id, energy_type, consumption, ...)
    
    ES->>DB: INSERT INTO energydata<br/>VALUES (1, now(), 'electricity', 100.5, ...)
    DB-->>ES: 插入成功
    
    ES->>ES: calculate_carbon_emission()<br/>计算碳排放
    ES->>DB: INSERT INTO carbon_emission<br/>VALUES (1, now(), ...)
    DB-->>ES: 插入成功
    
    ES-->>DS: EnergyData对象
    DS-->>Worker: 数据记录成功
    
    Worker->>AS: check_and_create_alarm()<br/>(device_id, data, timestamp)
    
    AS->>AS: load_thresholds()<br/>加载报警阈值配置
    
    alt 电流超限
        AS->>DB: INSERT INTO alarm<br/>VALUES (1, "过载报警", ...)
    end
    
    alt 电压异常
        AS->>DB: INSERT INTO alarm<br/>VALUES (1, "电压异常", ...)
    end
    
    AS-->>Worker: 报警检查完成
    
    Worker->>WS: broadcast()<br/>{type: "telemetry_update", data: {...}}
    WS->>Client: WebSocket推送实时数据
    Client-->>WS: 前端接收并更新UI
```

### 2.3 设备创建流程

```mermaid
sequenceDiagram
    participant C as 前端客户端
    participant API as devices.py
    participant Auth as get_current_user
    participant DS as DeviceService
    participant Registry as DeviceRegistry
    participant DB as PostgreSQL
    
    C->>API: POST /devices/<br/>{name:"1号水表", sn:"WATER001", device_type:"water_meter"}
    API->>Auth: 验证JWT Token
    
    alt Token无效
        Auth-->>API: AuthenticationException
        API-->>C: 401 未授权
    else Token有效
        Auth-->>API: User对象
        
        API->>DS: create_device_smart()<br/>(name, sn, device_type)
        
        DS->>Registry: get("water_meter")<br/>获取设备类型配置
        Registry-->>DS: DeviceTypeConfig<br/>{category:"water_meter", energy_type:"water", unit:"m³/h", ...}
        
        DS->>DB: 检查SN是否重复<br/>SELECT * FROM device WHERE sn='WATER001'
        
        alt SN已存在
            DB-->>DS: 已存在的设备
            DS-->>API: 返回现有设备
        else SN不存在
            DS->>DS: 自动填充字段<br/>device_category, energy_type, unit, rated_capacity
            
            DS->>DB: INSERT INTO device<br/>VALUES ('1号水表', 'WATER001', 'water_meter', 'water', ...)
            DB-->>DS: 插入成功，返回device_id
            
            DS-->>API: Device对象
        end
        
        API-->>C: 200 OK<br/>{id:1, name:"1号水表", device_type:"water_meter", energy_type:"water", ...}
    end
```

### 2.4 位置层级管理流程

```mermaid
sequenceDiagram
    participant C as 前端客户端
    participant API as locations.py
    participant LS as LocationService
    participant DB as PostgreSQL
    
    Note over C,DB: 场景1：创建顶级位置
    C->>API: POST /locations/<br/>{name:"A栋", location_type:"building"}
    API->>LS: create_location()<br/>(name, type, parent_id=None)
    LS->>LS: 计算层级<br/>level=0, full_path="/A栋"

    DB-->>LS: id=1
    LS-->>API: Location对象
    API-->>C: 200 OK {id:1, name:"A栋", level:0, full_path:"/A栋"}
    
    Note over C,DB: 场景2：创建子位置
    C->>API: POST /locations/<br/>{name:"3单元", location_type:"unit", parent_id:1}
    API->>LS: create_location()<br/>(name, type, parent_id=1)
    LS->>DB: 查询父位置<br/>SELECT * FROM location WHERE id=1
    DB-->>LS: {name:"A栋", level:0, full_path:"/A栋"}
    LS->>LS: 计算层级<br/>level=1, full_path="/A栋/3单元"
    LS->>DB: INSERT INTO location<br/>VALUES ("3单元", "unit", 1, 1, "/A栋/3单元")
    DB-->>LS: id=2
    LS-->>API: Location对象
    API-->>C: 200 OK {id:2, name:"3单元", parent_id:1, level:1}
    
    Note over C,DB: 场景3：查询位置树
    C->>API: GET /locations/tree
    API->>LS: get_location_tree()
    LS->>DB: 查询顶级位置<br/>SELECT * FROM location WHERE parent_id IS NULL
    DB-->>LS: [{id:1, name:"A栋"}, {id:3, name:"B栋"}]
    
    loop 每个顶级位置
        LS->>DB: 递归查询子位置<br/>SELECT * FROM location WHERE parent_id=1
        DB-->>LS: 子位置列表
        LS->>DB: 查询设备数量<br/>SELECT COUNT(*) FROM device WHERE location_id=1
        DB-->>LS: device_count
    end
    
    LS-->>API: 树形结构JSON
    API-->>C: 200 OK [{id:1, name:"A栋", children:[...]}]
```

### 2.5 设备分组管理流程

```mermaid
sequenceDiagram
    participant C as 前端客户端
    participant API as device_groups.py
    participant GS as DeviceGroupService
    participant DB as PostgreSQL
    
    Note over C,DB: 场景1：创建分组
    C->>API: POST /device-groups/<br/>{name:"生产线A", group_type:"production"}
    API->>GS: create_group()<br/>(name, type)
    GS->>DB: INSERT INTO device_group<br/>VALUES ("生产线A", "production", ...)
    DB-->>GS: id=1
    GS-->>API: DeviceGroup对象
    API-->>C: 200 OK {id:1, name:"生产线A"}
    
    Note over C,DB: 场景2：添加设备到分组
    C->>API: POST /device-groups/1/devices<br/>{device_ids:[1,2,3]}
    API->>GS: batch_add_devices_to_group()<br/>(device_ids, group_id=1)
    
    GS->>DB: 验证分组存在<br/>SELECT * FROM device_group WHERE id=1
    DB-->>GS: DeviceGroup对象
    
    loop 每个device_id
        GS->>DB: 验证设备存在<br/>SELECT * FROM device WHERE id=?
        DB-->>GS: Device对象
        
        GS->>DB: 检查是否已在分组中<br/>SELECT * FROM device_group_membership<br/>WHERE device_id=? AND group_id=1
        
        alt 已存在
            Note over GS: 跳过该设备
        else 不存在
            GS->>DB: INSERT INTO device_group_membership<br/>VALUES (device_id, 1, now())
            DB-->>GS: 插入成功
        end
    end
    
    GS-->>API: 成功添加的数量
    API-->>C: 200 OK {count:3, message:"成功添加3个设备"}
    
    Note over C,DB: 场景3：查询分组设备
    C->>API: GET /device-groups/1/devices
    API->>GS: get_devices_in_group(group_id=1)
    GS->>DB: SELECT device.* FROM device<br/>JOIN device_group_membership<br/>ON device.id = device_group_membership.device_id<br/>WHERE device_group_membership.group_id=1
    DB-->>GS: 设备列表
    GS-->>API: List[Device]
    API-->>C: 200 OK [{id:1, name:"设备1"}, ...]
```

### 2.6 设备维护管理流程

```mermaid
sequenceDiagram
    participant C as 前端客户端
    participant API as maintenance.py
    participant MS as MaintenanceService
    participant DB as PostgreSQL
    
    Note over C,DB: 场景1：创建维护计划
    C->>API: POST /maintenance/<br/>{device_id:1, type:"routine", scheduled_time:"2026-02-01 09:00"}
    API->>MS: create_maintenance()<br/>(device_id, type, scheduled_time, ...)
    
    MS->>DB: 验证设备存在<br/>SELECT * FROM device WHERE id=1
    DB-->>MS: Device对象
    
    MS->>DB: INSERT INTO device_maintenance<br/>VALUES (1, "routine", "2026-02-01 09:00", "scheduled", ...)
    DB-->>MS: id=100, 插入成功
    
    MS-->>API: DeviceMaintenance对象
    API-->>C: 200 OK {id:100, status:"scheduled"}
    
    Note over C,DB: 场景2：开始维护
    C->>API: POST /maintenance/100/start<br/>{operator:"张三"}
    API->>MS: start_maintenance(id=100, operator="张三")
    
    MS->>DB: UPDATE device_maintenance<br/>SET status='in_progress', actual_start_time=now()<br/>WHERE id=100
    DB-->>MS: 更新成功
    
    MS-->>API: 更新后的对象
    API-->>C: 200 OK {id:100, status:"in_progress"}
    
    Note over C,DB: 场景3：完成维护
    C->>API: POST /maintenance/100/complete<br/>{result:"正常完成", cost:500}
    API->>MS: complete_maintenance()<br/>(id=100, result, cost)
    
    MS->>DB: SELECT actual_start_time FROM device_maintenance WHERE id=100
    DB-->>MS: start_time
    MS->>MS: 计算维护时长<br/>duration = now() - start_time
    
    MS->>DB: UPDATE device_maintenance<br/>SET status='completed', actual_end_time=now(),<br/>duration_minutes=?, cost=500, result=?<br/>WHERE id=100
    DB-->>MS: 更新成功
    
    MS-->>API: 更新后的对象
    API-->>C: 200 OK {id:100, status:"completed", duration_minutes:120}
    
    Note over C,DB: 场景4：查询即将到来的维护
    C->>API: GET /maintenance/upcoming?days=7
    API->>MS: get_upcoming_maintenance(days=7)
    
    MS->>DB: SELECT * FROM device_maintenance<br/>WHERE status='scheduled'<br/>AND scheduled_time BETWEEN now() AND now()+7days<br/>ORDER BY scheduled_time
    DB-->>MS: 维护列表
    
    MS-->>API: List[DeviceMaintenance]
    API-->>C: 200 OK [{id:100, device_id:1, scheduled_time:"2026-02-01"}, ...]
```

## ⚙️ 3. 后台任务流程

### 3.1 MQTT消息监听流程

```mermaid
graph TD
    A[应用启动] --> B[main.py: lifespan startup]
    B --> C[start_mqtt_background<br/>启动MQTT后台监听]
    C --> D[创建MQTT Client]
    D --> E[连接MQTT Broker<br/>mqtt_broker:1883]
    E --> F[订阅主题<br/>mine/telemetry<br/>mine/device/+/telemetry]
    F --> G[client.loop_start<br/>后台线程启动]
    
    G --> H{收到MQTT消息?}
    H -->|是| I[on_message 回调]
    I --> J[process_data<br/>解析payload]
    J --> K[解析device_id]
    K --> L[DeviceService.report_device_data<br/>数据入库]
    L --> M[AlarmService.check_and_create_alarm<br/>检查报警]
    M --> N[WebSocket广播<br/>推送到前端]
    N --> H
    H -->|否| O[等待消息]
    O --> H
```

### 3.2 定时任务调度流程

```mermaid
graph TD
    A[应用启动] --> B[main.py: lifespan startup]
    B --> C[start_scheduler<br/>启动定时任务调度器]
    C --> D[创建BackgroundScheduler]
    D --> E{forecast_auto_update<br/>配置是否启用?}
    
    E -->|是| F[添加LSTM训练任务<br/>CronTrigger: 每天凌晨2点]
    E -->|是| G[添加预测更新任务<br/>IntervalTrigger: 每小时]
    E -->|否| H[跳过自动任务]
    
    F --> I[scheduler.start<br/>调度器启动]
    G --> I
    H --> I
    
    I --> J{到达触发时间?}
    
    J -->|LSTM训练时间到| K[auto_train_lstm_models]
    K --> L[训练系统负荷预测模型]

    N --> J
    
    J -->|预测更新时间到| O[auto_update_forecasts]
```

### 3.3 WebSocket实时推送流程

```mermaid
graph TD
    A[前端打开连接] --> B[WebSocket: /ws]
    B --> C[ConnectionManager.connect]
    C --> D[websocket.accept<br/>接受连接]
    D --> E[添加到active_connections列表]
    
    E --> F{保持连接}
    
    G[MQTT消息到达] --> H[mqtt_to_ws_callback<br/>回调函数]
    H --> I[asyncio.run_coroutine_threadsafe<br/>跨线程调度]
    I --> J[manager.broadcast<br/>广播消息]
    
    J --> K[遍历active_connections]
    K --> L{对每个连接}
    
    L --> M[connection.send_json<br/>发送消息]
    
    M -->|成功| N[继续下一个连接]
    M -->|失败| O[从列表中移除该连接]
    
    N --> L
    O --> L
    
    F -->|前端断开| P[ConnectionManager.disconnect]
    P --> Q[从active_connections移除]
```
