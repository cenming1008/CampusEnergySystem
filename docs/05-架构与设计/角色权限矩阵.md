# 角色权限矩阵

## 当前角色

- `admin`
  - 系统管理员
  - 可管理用户、模型训练/激活、数据清理、数据生成、调度查看、所有业务写操作

- `maintainer`
  - 运维/维护人员
  - 可配置设备、位置、分组、巡检、维护等业务对象
  - 可处理报警、执行巡检、写入业务数据
  - 不可管理用户、全量清库、训练或激活模型

- `operator`
  - 值班/操作人员
  - 可设备启停、处理报警、开始/完成巡检任务、提交巡检记录、写入设备/能源数据
  - 不可做系统配置类修改或用户管理

- `viewer`
  - 只读用户
  - 可访问查询类接口
  - 不可执行写操作

## 已落地的接口约束

- `admin` 独占
  - `/users/*` 管理员接口
  - `/data-cleanup/*`
  - `/data-generator/generate/*`
  - `/data-generator/clear/*`
  - `/forecast/scheduler/jobs`
  - `/forecast/lstm/train`
  - `/forecast/lstm/versions/*/activate`
  - `/forecast/lstm/hyperparameter-search`

- `admin` 或 `maintainer`
  - 设备创建/更新/删除
  - 位置创建/更新/删除与设备分配
  - 分组创建/更新/删除与设备绑定
  - 维护记录创建/更新/删除与状态流转
  - 巡检路线/点/计划/任务创建与配置修改
  - 负荷预测与可再生预测生成
  - LSTM 评估、版本列表、版本对比

- `admin` 或 `maintainer` 或 `operator`
  - 设备启停
  - 报警处理
  - 设备数据上报
  - 能源数据写入
  - 巡检任务开始/完成
  - 巡检记录提交

## 后续建议

- 已支持第一版位置范围控制：非 `admin` 用户可通过 `location_scope` 限制可访问的位置 ID 集合
- 当前已接入范围控制的读路径包括：设备列表/详情、设备数据、设备分析、报表导出
- 为读取类接口继续补充按角色的数据范围控制，而不只是“能不能调用”
- 将角色矩阵同步到前端菜单与按钮显示逻辑
- 在用户管理页加入角色变更与启停的二次确认
